# Исправления перед обновлением сервера — 02.10.2026

## Переходы с главной

Отдельный коммит `be4fcb7`, ветка `codex/fix-home-enter-project`, PR #116.
Регрессия воспроизведена на актуальном main: после загрузки второго проекта
статус снова становился `home` вместо `ready`.

`useRouterSync` запоминает последний обработанный адрес. Смена только
`bootStatus` больше не применяет старый `/` к новому состоянию. При реальной
смене адреса приоритет остаётся у URL. Обработчик принимает состояние `home`,
чтобы «Вперёд» мог вернуть загруженный проект, и отличает собственную запись
URL от внешней навигации, чтобы не закрыть задачу во время её загрузки.
Ссылка сбрасывается при новой авторизации. Ветка `root` с `goHome` сохранена;
таймеров и новых флагов стора нет. Семь новых интеграционных сценариев,
включая прямую загрузку панели задачи и повторный bootstrap после выхода.

Оболочка теперь монтирует палитру и общие диалоги на главной. Палитра открывается
по Ctrl+K; выбор уже загруженного проекта и задачи такого проекта действительно
входит в проект. Те же переходы исправлены в списке задач главного экрана.

## Обновление сервера

Изменения браузера, включая календарь, требуют пересборки образа client;
изменения писем требуют пересборки server. Один `git pull` работающие контейнеры
не обновляет. Сохранить локальные `.env`, `deploy.sh` и compose override.
Для текущей установки HTTPS: `CORS_ORIGIN=https://taskira.megafon.tj`,
`SESSION_COOKIE_SECURE=true`, `VITE_API_URL=`; скрипт сборки не должен заменять
пустой `VITE_API_URL` на localhost. Не удалять тома PostgreSQL и Minio.

Предыдущие принятые изменения трека K и аудита включены. Отклонённые эксперименты
с диалогами не возвращены; исходные замеры и ограничения стенда находятся
в `PERFORMANCE.md` и `AUDIT-2026-10-01.md`.

## Дополнение по ревью PR #116

Четыре новых регрессии воспроизвели проблемы первоначальной правки: медленный
резолв панели при переходе в другой проект, повтор эффектов в StrictMode,
канонизация `/` без изменения состояния при одном проекте и позднее появление
проекта в списке доступа. Дополнительно проверены поздний доступ к проекту
найденной задачи и отмена повторного резолва при обновлении списков.
Повторное ревью дополнительно проверено тестами: одинаковые списки доступа
не повторяют запрос, получение приглашения повторяет поиск недоступной задачи,
а ключ задачи другого проекта в query открывает этот проект с сохранением вида.
Списки сравниваются по нормализованным id и ключам, без зависимости от порядка
и идентичности массивов.

Адрес помечается обработанным после завершения попытки. Незавершённая попытка,
включая повтор после появления доступа, остаётся необработанной. Проект и панель
задачи применяются вместе после резолва ключа. Приоритет URL вычисляется первым
эффектом в порядке коммита; чтения ref во время рендера больше нет. Локальный
счётчик завершений обеспечивает канонизацию даже после операции без изменения
состояния. Изменений store и таймеров нет; ветка root с goHome сохранена.

Минимального сравнения ref оказалось недостаточно для отмены асинхронной работы
и операций без обновления состояния. Расширение ограничено useRouterSync;
существующие утверждения маршрутизации сохранены. Spy goHome имеет положительный
контроль и сопровождается проверками состояния и адреса.

CI предыдущего main прошёл функциональные проверки, включая LDAP, S3, SMTP,
восстановление и обновление БД, но Trivy обнаружил pcre2 10.48-r0 в nginx-образе
(CVE-2026-103111, исправлено в 10.49-r0). Dockerfile обновляет pcre2 вместе с
libexpat из репозитория Alpine. Исключения и ослабления проверки безопасности
не добавлялись; состав образа проверяется штатным CI.
