# Обновление создания проектов, справки и изображений

Перед запуском новой версии на существующей базе сделайте резервную копию PostgreSQL
с помощью `pg_dump -Fc` и проверьте, что архив читается командой `pg_restore --list`.
Храните архив вне контейнера и каталога, заменяемого при деплое. Обновление рабочей
базы без резервной копии не предусмотрено.

При запуске сервера применяется миграция `20261002T1700_project_labels_type.sql`.
Она исправляет старые `json`/`jsonb` в `projects.suggested_labels` на `text[]`,
сохраняя порядок, повторения и текст меток. SQL NULL становится пустым массивом.
Корректный столбец `text[]` остаётся без изменений. JSON null, объекты и элементы,
не являющиеся строками, останавливают транзакцию с сообщением `migration cancelled`.
Такие записи нужно проверить вручную; автоматически удалять их не следует.

Обновляйте клиент и сервер вместе: пять новых цветов принимаются новой серверной
валидацией. Старые цвета и настройки сохраняются. Цвет общий для организации;
статусы, приоритеты и права доступа не меняются.

Фото доски хранится в IndexedDB текущего браузера отдельно для пользователя и
проекта. На сервер оно не отправляется. Очистка данных браузера удаляет фото;
на другом устройстве его нужно выбрать заново. Фон применяется только за колонками.
Исходный файл фона должен иметь расширение PNG, JPG/JPEG, GIF или WebP и размер
не более 20 МБ. Проверка расширения не заменяет проверку декодирования изображения.

Для аватара выбирайте PNG, JPG/JPEG или GIF. Расширения проверяются до обработки,
затем изображение преобразуется в JPEG. WebP для аватара не поддерживается.
Ошибка выбора или загрузки сохраняет прежний аватар.

После деплоя проверьте создание проекта без шаблона и с шаблоном, справку RU/EN,
сохранение цвета, загрузку и замену фото доски, загрузку аватара и отклонение SVG.
Если миграция остановила запуск, изучите сообщение и старые данные до повторного
запуска. Для возврата старого типа столбца используйте проверенную резервную копию;
ручная обратная миграция в этот выпуск не входит.
