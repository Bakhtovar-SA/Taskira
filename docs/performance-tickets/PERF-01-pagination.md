# PERF-01 — End-to-end пагинация списка задач

Статус: open (остаётся keyset и ленивая клиентская загрузка). Приоритет: high.

## Наблюдение

На 50 000 активных задач и 200 пользователях p95 первой страницы равен
8 392 ms, глубокой страницы с `offset=49800` — 11 646 ms. При timeout 10 секунд
все 200 запросов глубокой страницы завершились timeout.

Диагностика и устранение подтверждённых Seq Scan/count описаны в
[`PERF-00-fix.md`](./PERF-00-fix.md): сервер больше не делает `count(*)` по
умолчанию и использует индекс порядка. Клиентский `listAllIssues()` всё ещё
последовательно дочитывает все страницы, а глубокий OFFSET всё ещё проходит
предыдущие записи индекса.

## Предлагаемая отдельная работа

Перевести API на cursor/keyset pagination, а UI — на серверные фильтры и
ленивую догрузку вместо полной гидратации проекта.
Добавить план запроса (`EXPLAIN ANALYZE`) и benchmark 10k/50k до и после.

## Критерий приёмки

p95 первой и последующей страницы при 50k/200 не выше 1 500 ms, без timeout;
открытие проекта не инициирует автоматическую загрузку всех 50 000 строк.
