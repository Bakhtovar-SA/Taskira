# PERF-01 — End-to-end пагинация списка задач

Статус: open. Приоритет: high. Не входит в ТЗ 1.6.

## Наблюдение

На 50 000 активных задач и 200 пользователях p95 первой страницы равен
8 392 ms, глубокой страницы с `offset=49800` — 11 646 ms. При timeout 10 секунд
все 200 запросов глубокой страницы завершились timeout.

Сервер ограничивает ответ 200 строками, но каждый запрос делает `count(*)`, а
клиентский `listAllIssues()` последовательно дочитывает все страницы. Поэтому
формальная пагинация не ограничивает объём загрузки проекта. Глубокий OFFSET
добавляет стоимость по мере роста набора.

## Предлагаемая отдельная работа

Перевести API на cursor/keyset pagination, не считать total на каждой странице,
а UI — на серверные фильтры и ленивую догрузку вместо полной гидратации проекта.
Добавить план запроса (`EXPLAIN ANALYZE`) и benchmark 10k/50k до и после.

## Критерий приёмки

p95 первой и последующей страницы при 50k/200 не выше 1 500 ms, без timeout;
открытие проекта не инициирует автоматическую загрузку всех 50 000 строк.
