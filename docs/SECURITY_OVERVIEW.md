# Taskira: обзор безопасности для закупки

Этот документ описывает стандартную однохостовую on-prem инсталляцию Taskira.
Он не является сертификатом или отчётом пентеста.

## Аутентификация и сессии

Taskira работает в режиме `local` либо интегрируется с LDAP/Active Directory.
В local-режиме пароли хранятся только как bcrypt-хэши. Новый локальный и
break-glass пароль должен содержать минимум 14 символов, три из четырёх групп
символов, не включать логин и не совпадать с известным дефолтом. Сервер не
запускается без `ADMIN_PASSWORD` или с небезопасным значением.

После пяти неудачных попыток известная учётная запись по умолчанию блокируется
на 15 минут. Дополнительно действуют лимиты по IP для логина и по пользователю
для всего API. Значения настраиваются через env. Ответ входа не раскрывает,
существует ли логин.

Сессия — подписанный JWT в cookie `HttpOnly; SameSite=Strict` (`Secure` при
HTTPS). Абсолютный срок — 8 часов без продления, активная браузерная сессия
ротируется раз в час внутри этого срока. Logout, деактивация и смена роли увеличивают серверную `session_version`,
поэтому ранее выданные и ротированные токены отзываются.

В LDAP-режиме пароль пользователя проверяет каталог и Taskira его не хранит.
Локальная учётная запись администратора остаётся break-glass доступом; её пароль
подчиняется той же политике. 2FA в Taskira отсутствует: для LDAP его следует
реализовывать политиками AD и корпоративного доступа.

## Права доступа

Сервер является источником истины. Глобальный администратор управляет ресурсом.
В проекте есть manager, employee и viewer. Manager изменяет любые задачи своего
проекта; employee изменяет и перемещает только задачи, где он автор или
исполнитель; viewer читает. Проверки выполняются сервером на каждой операции,
а не только скрытием кнопки в UI.

## Данные и шифрование

- PostgreSQL хранит пользователей, проекты, задачи, настройки и audit log.
- Вложения и аватары находятся в отдельном local volume либо настроенном
  S3/MinIO; в PostgreSQL лежат только метаданные и ключ объекта.
- Пароли local-пользователей — bcrypt-хэши. JWT, пароли БД и интеграций задаются
  через `.env` и не входят в backup или support bundle.
- Шифрование дисков, PostgreSQL/S3 at rest и защита файла `.env` обеспечиваются
  ОС и инфраструктурой клиента. Taskira не заявляет собственное шифрование at
  rest поверх этих механизмов.
- Для шифрования трафика ставится корпоративный HTTPS reverse proxy; при HTTPS
  включается `SESSION_COOKIE_SECURE=true`. Сервер фронта отдаёт CSP без
  `unsafe-inline`, HSTS, nosniff, Referrer-Policy и запрет фреймов.

## Сеть

В стандартном Compose наружу публикуется только TCP `CLIENT_PORT` (по умолчанию
8081). API 8080 и PostgreSQL 5432 доступны только внутри compose-сети. Для LDAP,
SMTP или S3 открываются исходящие соединения только к адресам, явно заданным
администратором. Taskira не использует telemetry, внешний registry, CDN,
проверку обновлений или иной обязательный внешний сервис. После переноса
релизного архива установка и работа возможны без интернета.

## Audit log и SIEM

Журнал содержит ISO-время, actor, action, object, result (`success`, `denied`,
`error`) и структурированные details. Глобальный администратор выгружает его в
JSON Lines (одна JSON-запись на строку) или CSV:

```bash
curl -fsS -H "Authorization: Bearer $TOKEN" \
  'https://taskira.example/api/admin/audit-log/export?format=jsonl&limit=100000' \
  -o taskira-audit.jsonl
jq -c '{timestamp,actor,action,object,result}' taskira-audit.jsonl

curl -fsS -H "Authorization: Bearer $TOKEN" \
  'https://taskira.example/api/admin/audit-log/export?format=csv&limit=100000' \
  -o taskira-audit.csv
awk -F, 'NR==1 || /denied/' taskira-audit.csv
```

Параметры `from` и `to` принимают ISO-дату со смещением, например
`2026-09-01T00:00:00Z`. Один запрос ограничен 100 000 строками. Заголовок
`X-Taskira-Truncated: true` означает, что период следует разделить на окна;
`X-Taskira-Limit` сообщает применённый предел. Выгрузка сама фиксируется
событием `audit.export`.

## Полный экспорт данных инсталляции

Глобальный администратор может в любой момент выгрузить все данные инсталляции
одним потоковым запросом — ответ на вопрос «можем ли мы забрать свои данные»,
который в корпоративной закупке звучит как пункт договора, а не пожелание:

```bash
curl -fsS -H "Authorization: Bearer $TOKEN" \
  'https://taskira.example/api/admin/export' \
  -o taskira-export.jsonl
jq -c 'select(.type == "issue")' taskira-export.jsonl | head
```

Формат — NDJSON (одна запись на строку, поле `type` определяет сущность:
`project`, `issue`, `comment`, `checklistItem`, `customField`/`customFieldValue`,
`issueLink`, `attachment` (только метаданные и `storageKey`, не содержимое файла),
`user` (без `passwordHash`), `auditLogEntry` и т.д.). Первая строка — `meta` с
`schemaVersion`, чтобы будущий импорт (отдельная задача, ещё не реализован) мог
отклонить формат, который не понимает. Ответ отдаётся потоково постранично
(партиями по 1000 строк на таблицу), поэтому размер инсталляции не ограничивает
доступную память процесса. Содержимое вложений — не в этом ответе: используйте
`scripts/backup.sh` (полный офлайн-бэкап, экспортирует и БД, и хранилище вложений
рядом) или сопоставьте `storageKey` из экспорта с бакетом напрямую. Личные
настройки экрана (сохранённые вьюхи, избранные проекты) в экспорт не входят —
он про рабочие данные организации, не про персональные предпочтения интерфейса.
Каждый запрос фиксируется событием `admin.export` в audit log.

## Поставка, сканирование и восстановление

Релиз — офлайн-архив с versioned images, manifest и SHA-256. `install.sh`
проверяет контрольные суммы до загрузки образов. CI выполняет `npm audit` и
Trivy для client/server и падает на High/Critical. Исключения допускаются только
в `.trivyignore.yaml` с причиной, владельцем и сроком; по умолчанию список пуст.

`backup.sh` создаёт единый проверенный архив PostgreSQL и вложений,
`restore.sh` проверяет целостность и совместимость схемы. `support-bundle.sh`
собирает метаданные и логи с редактированием секретов, без строк задач и
содержимого вложений. Процедуры, RPO/RTO и результат репетиции описаны в
`OPERATIONS.md`.
