# Файлы проекта

Каталог `/p/:projectKey/files` собирает вложения задач проекта, включая архивные. Вкладка «Файлы» расположена последней среди представлений проекта. Данные и файлы остаются у исходной задачи: каталог не создаёт копии.

## Использование

- Поиск по имени файла, ключу и названию задачи.
- Фильтры: изображения, документы, архивы, другие файлы.
- Сортировка: сначала новые или старые, по названию, сначала большие.
- Страницы по 50 записей; поиск, фильтр, сортировка и страница сохраняются в URL.
- Имя файла и кнопка скачивания используют существующий API вложений. Название задачи открывает её обычную карточку.
- Добавление и удаление выполняются в исходной задаче. Вложения архивных задач остаются доступны. Для обновления каталога после изменения вложений используется «Обновить».

Например, руководитель ищет протокол по слову «портал», открывает задачу-источник из найденной строки и просматривает результат работы. Для скачивания не требуется искать вложение среди комментариев. Прямой загрузки файлов в проект нет.

## Доступ и API

`GET /api/projects/:projectId/files` требует проектного права `browse`. Приглашение к отдельной задаче не открывает каталог проекта. Скачивание дополнительно проверяет доступ к исходной задаче через существующий маршрут вложений.

Проверка доступа выполняется перед валидацией фильтров: некорректный запрос не меняет отказ 401/403 для пользователя без доступа. Участник проекта получает ошибку 400 при неверных параметрах.

Контракт запросов и ответов: [contract.ts](../server/src/contract.ts) (`ProjectFilesQuery`, `ProjectFileDto`, `ProjectFilesResultDto`). Реализация: [projectFiles.ts](../server/src/routes/projectFiles.ts). Поиск параметризован, сортировка выбирается из закрытой карты; внутренние ключи файлового хранилища в выдачу не входят. Новых таблиц, миграций и зависимостей нет.

Связь вложений с задачами использует существующий индекс `idx_attachments_issue` на `attachments(issue_id)` из [миграции 010](../server/migrations/010_attachments.sql). Точные число файлов и суммарный размер рассчитываются по всей отфильтрованной выборке проекта при каждом запросе страницы; отдельный кэш итогов не добавлен.

Отбор задач проекта поддерживает существующий индекс `idx_issues_project_status` с первым столбцом `project_id` из [миграции 001](../server/migrations/001_init.sql). Эти индексы помогают ограничить каталог проектом, но не ускоряют подстрочный поиск через `strpos(lower(...))` и точные агрегаты. Лимит страницы ограничивает ответ, а не объём вычислений. Для проектов с десятками тысяч вложений требуется отдельный замер `EXPLAIN (ANALYZE, BUFFERS)` на характерных данных; гарантии производительности для такого объёма нет. Общего ограничения числа файлов в каталоге нет: скрытое усечение нарушило бы полноту поиска и итогов.

Размеры в API представлены числами JavaScript. Целочисленная точность суммы гарантируется до `Number.MAX_SAFE_INTEGER` байт (около 8 ПиБ); суммы выше этого предела могут округляться.

Предусмотрены отмена устаревших запросов, сообщение об ошибке с повтором, пустая выдача и сброс фильтров. Ссылка на исчезнувшую страницу возвращает на последнюю существующую, сохраняя фильтры. Параллельные скачивания имеют независимые состояния ожидания.

## Интерфейс и движение

Раздел использует действующие [токены и компоненты Taskira](design/DESIGN.md), светлую и тёмную темы. На узком экране таблица становится последовательностью строк с переносом длинных имён. Очистка поиска возвращает фокус в поле.

Графики обзора, дашбордов и отчётов анимируют геометрию за 450 мс (`--dur-5`), сохраняя итоговые подписи и доступные таблицы. Запуск ждёт появления в видимой области и окончания навигационного перехода. Изменение данных повторяет эффект; наведение и изменение размера не перезапускают его. Системное и личное уменьшение движения отключают эффекты. Реализация: [chartMotion.css](../src/dashboards/chartMotion.css), [useChartReveal.ts](../src/dashboards/useChartReveal.ts).

Общие исправления сохраняют прокрутку активного варианта Combobox, повторное открытие после Escape и корректную блокировку формы; Popover выбирает доступный элемент для фокуса; Menu и Select корректно обрабатывают поиск по буквам и повторное открытие. Подложка активной вкладки учитывает загрузку шрифта, а горизонтальная навигация прокручивает собственную полосу.

Функция загружается отдельным клиентским чанком. Изменение бюджетов сборки описано в [PERF-BUDGET.md](design/PERF-BUDGET.md).

Тексты экрана находятся в общих словарях `src/i18n/ruLazy.ts` и `src/i18n/en.ts`, выводятся через `t()` и загружаются перед экраном через `lazyView()`. Размеры, итоги и номера страниц используют тот же словарь; названия задач и файлов остаются пользовательскими данными.

## Проверка

- Клиентские регрессии: [ProjectFilesView.test.tsx](../src/components/ProjectFilesView.test.tsx), тесты общих компонентов и графиков.
- Сервер: [projectFiles.test.ts](../server/test/projectFiles.test.ts), манифест маршрутов и проверка ответов по контракту.
- Регрессия большого каталога: 5 000 вложений в 1 000 задач, точные итоги поиска, последняя страница, выборочный поиск и запрос за пределами выдачи с `offset=1000000`. Временные пороги в тест не зашиты.
- Стандартные проверки: `npm run typecheck`, `npm test`, `npm run lint`, `npm run build`, `npm run bundle:check`, `npm run docs:check`, проверки цветов, движения, контраста и прав.
- Браузерные сценарии: поиск, пустая выдача, сброс фильтров, исходная задача, скачивание, прямые ссылки, узкий экран, обе темы, графики и клавиатура. Ограничение: системный reduced-motion проверяется исходниками и motion checker; эмуляция настройки ОС вручную не выполнялась.

Справка RU/EN описывает каталог и правила вложений. Дополнительные модули рабочего пространства в эту поставку не входят.
