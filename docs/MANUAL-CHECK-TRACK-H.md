# Ручная проверка Трека H

Проверять на тестовой установке, в светлой и тёмной теме, с RU и EN. Для административных действий нужен
администратор; для проверки запретов — менеджер, сотрудник и наблюдатель. Изменения компонентов не меняют
права и вызовы API. Реальные загрузки файлов, LDAP и удаление проверять только на тестовых данных.

## Экраны

## Проверки исполнителя

- Клиентские проверки: `npm run typecheck`, `npm test`, сборка и проверки бандла/цветов/контраста/анимаций/анти-списка.
- Chrome: снимки и axe для 24 адресов/состояний в light/dark с изолированными ответами API; проверка реального
  интерфейса приложения, включая гостевой режим, виджеты и оболочку настроек. Это проверка отображения, а не
  подтверждение работы боевого API или реальных загрузок файлов.
- Клавиатура в обеих темах: уведомления, профиль, переключатель проектов, мастер проекта и диалог спринта.
  Проверка открытого `ds/DatePicker` обнаружила `aria-required-children` и `aria-required-parent`: gridcell
  расположен непосредственно в grid без row. В спринтах сохранены нативные даты; исправление общего календаря
  записано в «Нужно в ds», файл компонента не менялся.
- `/dev/ui`: на Windows прошли axe и клавиатура (5 тестов); 24 сравнения снимков отличаются от Linux-эталонов
  отрисовкой шрифтов. Эталоны не изменялись. Полный `npm run test:ui` выполняет Linux CI на PR; workflow теперь
  реагирует также на изменения экранов и виджетов.

Сохранённые исключения перечислены в [«Нужно в ds»](tracks/TRACK-H-DS-SCREENS.md#нужно-в-ds). Файлы компонентов
`src/ds`, токены, CSS и эталоны браузерных снимков не менялись. Дополнительные UI-исправления
затрагивают общий `Modal` в `src/ui.tsx`, ленивые модалки и доску: проверить сохранение черновика
при первом открытии, фокус после загрузки и отсутствие повторного скачка карточки после обновления колонок.
