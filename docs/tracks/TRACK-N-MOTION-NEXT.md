- **[код]** — подтверждено чтением кода, указан файл:строка (на `9368a4d`);

**P2** — полировка. «Бюджет» — оценка влияния на `scripts/bundle-budget.json` (gzip).

## Зачем

ADR-0035 (`docs/adr/0035-motion-library-spike.md`, Accepted 13.10.2026) ввёл пружины и FLIP через одну обёртку
`src/motion.ts` с ленивым чанком `src/motionEngine.ts` (`motion/mini` `animate` + `spring`, motion 13.4.4). Движение
перенесли со стенда тремя заходами за два дня. Разбор показал:

1. motion/mini по окончании анимации **пишет последний кадр в inline-стиль** элемента. Из-за этого после
   разворачивания сайдбара ручка ширины перестаёт работать, а у карточек доски пропадают стили перетаскивания. **[запуск]**
2. Личный выключатель «Уменьшить движение», обещанный в «Последствиях» ADR, не подключён: нет интерфейса, CSS его
   не видит, часть кода смотрит только на системную настройку. Есть движения без reduced-motion вообще. **[код]**
3. `motion:check` не видит пружины, задержки, CSS-transition и длительности в JS. Пресет `SPRING_POP`
   успокаивается 650 мс при пределе ADR в 500 мс. **[запуск]**
4. Нестабильный `board-layout` воспроизведён: 1 падение на 144 прогона, расхождение 0.009 px —
   «хвост» transform-анимации. **[запуск]**
5. Запас бюджета бандла меньше 1 КиБ по `total` и по `js`. Любое новое движение упирается в решение владельца. **[запуск]**

## 1. Исправления

### FIX-01 · P0 · Остаточные inline-стили после пружины (motion/mini фиксирует последний кадр)

**Причина [код]:** `motion/mini` `animate` → `framer-motion/dom/mini` → `animateElements` → `NativeAnimation`.
В `node_modules/motion-dom/dist/es/animation/NativeAnimation.mjs:36-53` обработчик `onfinish` вызывает
`setStyle(element, name, keyframe)` и `animation.cancel()`. Значит, после каждой законченной анимации движка на элементе
остаётся inline-стиль последнего кадра. Это CSSOM, CSP не нарушается, но inline-стиль перебивает классы.

**Последствия:**

- **Сайдбар [запуск].** `glideWidth` (`motion.ts:209-214`, вызов — `Sidebar.tsx:185-192`) оставляет на
  `aside.sidebar-expanded` `style.width = "248px"`. Ручка ширины меняет только `--sidebar-width`
  (`SidebarResizeHandle.tsx:24`), а правило `.sidebar-expanded { width: var(--sidebar-width…) }`
  (`styles/navigation.css:47`) проигрывает inline-ширине. Как воспроизвести: 1920×1080, чанк загружен, свернуть, развернуть,
  потянуть ручку на +88 px. Ширина до 248, после 248. В тот же класс бед — по коду — попадают выезжающая панель
  (`max-lg:w-[304px]`, `Sidebar.tsx:321`) после сужения окна и ширина по умолчанию 304 px на экранах ≥ 2560 px.
  Это **[гипотеза]**: следствие того же inline-стиля, отдельно не запускалось.
- **Новая карточка доски [запуск].** `enter(card)` (`Board.tsx:135-137`) оставляет `opacity: 1; transform: none`. У такой
  карточки `[data-dragging]` даёт `opacity` 1 вместо 0.45 (`index.css:353-358`): силуэт на месте не бледнеет.
- **Соседи после FLIP [запуск].** `flipFrom` завершается кадром `translate(0px, 0px)` (`motion.ts:148`), и он остаётся
  inline. У «призрака» перетаскивания (`Board.tsx:287-304` клонирует карточку вместе с inline-стилем) правило
  `.drag-ghost > .board-card { transform: rotate(2deg) }` (`index.css:369-372`) не действует: вычисленный transform —
  `matrix(1, 0, 0, 1, 0, 0)` вместо поворота. Ненулевой transform также делает карточку контекстом наложения и
  containing block для fixed-потомков. Последствия этого **[гипотеза]**, сейчас fixed-потомков у карточки нет.
- **Строки списка, окна, бейджи [код]:** то же для `flipFrom`/`enter` в `listExit.ts:81`, `listEnter.ts:27`,
  `ds/Dialog.tsx:56`, `usePulse.ts:12`. Видимых поломок не найдено.

**Что сделать:** в `motion.ts` после `finished` анимации движка снимать записанные motion свойства (`opacity`,
`transform`, `width`), если элемент не перехвачен новой анимацией (`running.get(el) === c`). Это не касается `glideTo`: он
сам ставит inline-место индикатора, и оно должно остаться. Делать это внутри `track()`/`done()`, а не в вызывающих.
Альтернатива, которая убирает причину целиком, — IMP-03.
**Проверка:** Playwright-тесты CHK-04 (а), (б), (в): после развёртки ручка меняет ширину; после переноса
`card.style.transform === ""` и `style.opacity === ""`; призрак повёрнут. Юнит: фейковый движок, `finished` резолвится →
inline-свойства сняты, кроме перехваченного элемента.
**Риск:** низкий. Снятие inline-стиля в момент, когда CSS даёт то же значение, — без скачка. Проверить вход окна:
`transform: none` у `<dialog>` после снятия не должен давать скачка (у `.ds-dialog` нет своего transform). **Бюджет:** < 0.1 КиБ вход.

### FIX-02 · P1 · Личный выключатель «Уменьшить движение» не подключён

**[код]** `motion.ts:22-44`: выключатель есть только в JS. Включить его можно только через `localStorage["taskira.reduceMotion"]`
или `setReducedMotion(true)`. Интерфейса нет, атрибута `data-motion` на `<html>` нет (`grep data-motion src public` пусто).
ADR-0035 («Последствия») обещал выключатель в «Оформлении» и его действие на CSS. Сейчас при включённом выключателе:

- все CSS-анимации (`anim-*`, `.ds-pop`, `hintIn`, `viewIn`, `drawLine`, уход окон) продолжают играть;
- `theme.ts:126, 143` (круг смены темы), `ds/Presence.tsx:24`, `RoadmapView.tsx:94`, `DocsView.tsx:26` смотрят только на
  системную `prefers-reduced-motion`;
- `ds/Dialog.tsx:96` смотрит на `motionReduced()`. Окно закрывается мгновенно, а `Presence` держит его ещё 320 мс:
  поведение разное.

**Что сделать:** (1) переключатель в личных настройках рядом с выбором темы (`src/components/settings/PersonalSettings.tsx:163`,
карточка `settings.appearance.theme`) — ключи словаря `settings.appearance.reduceMotion*` в `ru.ts` и `en.ts`. Компонента
`AppearanceSettings`, который упоминает `CLAUDE.md` (раздел i18n), в `src/` уже нет; (2) `public/theme-init.js` ставит `data-motion="reduce"` до первой
отрисовки, `setReducedMotion` — при переключении; (3) одна точка истины `motionReduced()` для всех мест выше;
(4) CSS — по IMP-05. Без интерфейса пункт не закрыт: это ответ ADR для пользователей VDI без системной настройки.
**Проверка:** юнит `setReducedMotion` → `documentElement.dataset.motion`; Playwright: включить выключатель, пройти доску,
окно и тост — `document.getAnimations()` пуст сразу после действия (CHK-04 г).
**Риск:** CSS-бюджет (IMP-05). Требует решения владельца по месту в интерфейсе. **Бюджет:** ≈ 0.2–0.4 КиБ JS/CSS.

### FIX-04 · P1 · Длительности вне правил ADR и ТЗ 5.13

- **[запуск]** `SPRING_POP = { visualDuration: 0.3, bounce: 0.4 }` (`motion.ts:172`): `spring.applyToOptions` даёт
  **650 мс** успокоения, при пределе ADR в 500 мс. `SPRING` даёт 500, `SPRING_ENTER` — 350. Команда:
  `node -e 'const {spring}=require("motion");console.log(spring.applyToOptions({visualDuration:0.3,bounce:0.4}).duration)'`.
  Тест `motion.test.ts:141-150` проверяет только `SPRING` и `SPRING_ENTER`.
- **[код]** `flash` — 400 мс (`motion.ts:197`), фолбэк `glideWidth` — 250 мс (`motion.ts:213`). Это не токены (100/150/200/300/450).
  Проверка JS сравнивает только с потолком 450 (`check-motion.mjs:101-102`).
- **[код]** задержки по очереди складываются с длительностью и выходят за 450 мс: `.anim-stagger` — 240 + 300 = 540 мс
  (`index.css:1045-1053`); отчёты — сноска 320 + 300 = 620 мс (`styles/reports.css:61-63`); «Главная» — 120 + 300 = 420 мс
  (`styles/workspace.css:700-703`, в пределах). Задержки `motion:check` не считает.

**Что сделать:** `SPRING_POP` → `{ visualDuration: 0.25, bounce: ≤ 0.3 }`, подобрать так, чтобы было ≤ 500 мс, и добавить его
в тест; `flash` → `--dur-5` (450) или `--dur-4` (300); фолбэк `glideWidth` → 200 или 300; сократить шаг задержки
(40 → 30 мс, потолок `n+5`) так, чтобы задержка + длительность ≤ 450. **Проверка:** расширенный `motion:check` (IMP-02).
**Риск:** визуально минимальный. **Бюджет:** 0.

### FIX-06 · P1 · Принудительные пересчёты раскладки в циклах FLIP

**[код]** `flipFrom` сначала отменяет текущую анимацию (`track(el, null)` — запись), затем читает `getBoundingClientRect`
(`motion.ts:138-139`). Её вызывают в цикле:

- `boardFlip.ts:131-139`: на каждый сдвинувшийся элемент, а перед этим `fly()` вставляет узел в `body`
  (`boardFlip.ts:153-165`) — чтение и запись чередуются, до 40 пересчётов за коммит;
- `listExit.ts:77-82`: до 199 пересчётов (FIX-05).

Кроме того, `playBoardFlip` висит на layout-эффекте каждой колонки (`Board.tsx:346`). Пока снимок жив (3 с, или ≈ 10 с
после массовой смены), каждая колонка заново обходит **все** карточки: `querySelectorAll` + `getComputedStyle` + rect,
`boardFlip.ts:113-118`.
Порядок величины на слабом CPU — **[гипотеза]**, не замерялось.
**Что сделать:** передавать в `flipFrom` уже измеренное «последнее» положение (`last`) необязательным параметром; в
`playBoardFlip` сначала прочитать всё, затем писать; проигрывать снимок один раз за коммит (флаг до следующего
микротаска или проверка «уже проигран для этого набора строк»). **Проверка:** CHK-05 — число событий `Layout` в трассировке
Chromium на перенос в доске из 200 карточек при CPU 4× и 6×: до и после. Критерий — не больше 2 принудительных пересчётов
на коммит. **Риск:** средний, затрагивает прерывание пружины; держать тесты `boardFlip.test.ts` зелёными. **Бюджет:** ≈ 0.1 КиБ вход.

### FIX-07 · P1 · Свёртка сайдбара анимирует `width` — раскладка всей рабочей области на каждом кадре

**[код]** `glideWidth` ведёт WAAPI по `width` (`motion.ts:206-214`) ≈ 500 мс (`SPRING`). Ширина `aside` меняет раскладку

только визуальный «корпус» (transform/clip-path на подложке), а раскладку переключать один раз в конце. Вариант (б) —
только с решением владельца: это меняет внешний вид. **Риск:** средний. **Бюджет:** 0–0.2 КиБ.

### FIX-09 · P1 · Обёртка экрана `anim-fadeup` двигает всё содержимое и навсегда оставляет transform

**[код]** `App.tsx:317`: `<div key={ui.view} className="anim-fadeup h-full">`. При каждой смене вида это `translateY(4px)` → 0

### FIX-10 · P2 · Гонка `vt-nav` при быстрой смене видов

### IMP-03 · P1 · Решение владельца: пружины без рантайма motion (статические `linear()`)

### Правила для исполнителя

1. Ветка от свежего `origin/main` (`git fetch origin && git switch -c <имя> origin/main`), один PR на пункт или тесно
   связанную группу. PR — **черновик** в `main`, описание на русском: что, зачем, как проверено (команды и результаты),
   ID пунктов трека.
2. Ответить на **все** комментарии ревью: исправление со ссылкой на коммит или аргументированный отказ. Не закрывать
   обсуждения молча.
3. Слияние — **только по явной команде владельца** и после зелёных CI-проверок, включая `ui-visual`. Не сливать самому,
   не включать auto-merge.
4. Перед каждым PR — CHK-07 полностью. После `git pull`/`merge` — `npm ci` (CLAUDE.md, «Commands»).
5. Сгенерированные файлы не править руками: `docs/PERMISSIONS.md`, `docs/MIGRATION-LIST.md`, `docs/API-SCHEMAS.md`,
   `src/permissions.matrix.ts`, `server/src/permissions.matrix.ts`; новые генерируемые (IMP-01) — только скриптом
   с `--check` в CI.
6. Цвета — только токены (`npm run colors:check`). Сырых `#hex`/`rgb()` в компонентах нет; WAAPI-кадры — через
   `var(--…)`/`color-mix`, как `flash` (`motion.ts:197`).
7. Длительности — только `--dur-1…5`; пружины — только пресеты обёртки; ≤ 450 мс (пружина — ≤ 500 мс успокоения).
