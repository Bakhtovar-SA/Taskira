## J1. Сервер: задачи без срока

Календарю нужен список «Без срока» (как панель «Unscheduled» в Jira). Фильтра «срок не задан» сейчас нет.

- `server/src/contract.ts` `IssueFilterQuery`: `dueEmpty: z.literal("1").optional()` рядом с `dueFrom`/`dueTo` —
  `due_date IS NULL`. Вместе с любым другим условием по сроку — `dueFrom`, `dueTo`, `overdue` — в одном запросе 400
  (условия противоречат друг другу), а не пустой набор.
- Где проверять: **не** `.refine` на `IssueFilterQuery` — на нём строятся `IssueQuery = IssueFilterQuery.extend(…)` и
  `IssueCountsQuery`, а `.refine` превращает схему в `ZodEffects` без `.extend()`. Проверка — в начале
  `buildIssueFilter()` (`services/issueFilters.ts`), общем для списка и счётчиков: `throw new ApiHttpError(400,
  "VALIDATION", …)` из `errors.ts` (как в `services/dashboards.ts`). Код `VALIDATION` уже есть в словаре ошибок клиента.
- В `SavedViewFilter` **не** добавлять: это параметр просмотра календаря, не условие сохранённой вьюхи.
- Индекс не нужен: выборка идёт внутри проекта по существующим индексам; если `EXPLAIN` на 50 000 задач покажет Seq Scan
  по всей таблице — записать замер в PR и обсудить, а не добавлять индекс молча.
- Тест сервера: `dueEmpty=1` отдаёт только задачи без срока; права и архив — как у остального списка; `dueEmpty` +
  `dueFrom`, `dueEmpty` + `dueTo`, `dueEmpty` + `overdue=1` → 400 — и для списка, и для `…/issues/counts`.

## J2. Календарь проекта

Образец — календарь Jira (скриншот владельца): сетка месяца с понедельника, задача — плашка в дне своего срока.

**Место и адрес**
- `ViewId` `"calendar"`, адрес `/p/:projectKey/calendar` (`src/router.ts`, `samePlace()`, тест роутера); вкладка в шапке
  проекта после «Таймлайна» (`PROJECT_VIEWS` в `Sidebar.tsx`), иконка — новая `IcCalendar` в `src/icons.tsx` в стиле
  набора (duotone, `tone`), подпись «Календарь» / “Calendar”.
- Клавиши: `1` Доска, `2` Список, `3` Таймлайн, `4` Календарь, `5` Спринты (если модуль включён). Обновить `App.tsx`,
  подсказки `kbd` во вкладках, окно «Горячие клавиши», справку (`DocsView`, RU и EN).
- Палитра команд: «Календарь» с синонимами (`calendar`, `календарь`, `kalendar`) — как у таймлайна в `CommandPalette.tsx`.
- Проектом «по умолчанию» календарь **не** становится: `projects.default_view` ограничен CHECK в миграции, менять его —
  отдельное решение.

**Что показывает**
- Месяц (6 недель, высота не прыгает) и неделя (одна строка, ячейки выше). Переключатель «Месяц / Неделя» — `Tabs` из `ds`, как
  масштаб таймлайна; выбор — в `localStorage` `taskira.calendar.mode`.
- Шапка: «Сегодня», ‹ ›, название периода («октябрь 2026», «5–11 октября 2026»), поиск по названию и ключу, фильтр
  исполнителя и типа (те же параметры `GET …/issues`, что у Списка), флажок «Скрыть закрытые» (`closed=hide`), кнопка
  панели «Без срока». Выходные — показаны, но приглушены токеном; сегодня — отметка как в `DatePicker`.
- Плашка задачи: иконка типа, ключ, название (обрезка с многоточием), аватар первого исполнителя. Просроченная открытая
  задача — цвет опасности (как срок на карточке доски); закрытая — приглушена и с зачёркнутым названием. Цвет плашки — по
  категории статуса токенами `--status-*`, не по проекту.
- В дне больше 3 плашек (месяц) — «ещё N»: `Popover` из `ds` со всеми задачами дня. В неделе — прокрутка внутри ячейки.
- Данные: `GET …/issues` с `dueFrom`/`dueTo` = видимый диапазон (с днями соседних месяцев), сортировка по сроку, потом по
  приоритету; все страницы диапазона, но не больше 500 задач — дальше строка «Показаны первые 500 — уточните фильтр».
  Задачи перечитываются по `issuesRevision`, как на доске. Архивные не показываются.
- Панель «Без срока» (`SidePanel` или колонка справа, закрывается): `dueEmpty=1` постранично, те же фильтры.

**Действия**
- Клик по плашке — задача правой панелью (`ui.issueMode = "panel"`, как из доски); `J`/`K` идут по плашкам в порядке
  дней (`data-issue-id`, `src/issueNav.ts`).
- Перетаскивание плашки на другой день или из «Без срока» в день — ставит срок (`updateIssue(id, { dueDate })`); на
  «Без срока» — снимает. Нативный HTML5 DnD (ADR-0007), как на доске. Без права `edit` на задачу (`can()`) плашка не
  тащится, а причина — в подсказке. Ошибка сервера возвращает плашку на место и показывает `errText`.
- Клавиатура вместо мыши: в фокусе плашки `M`/`Ь` открывает `DatePicker` срока этой задачи (тот же, что в карточке).
- Кнопка «+» при наведении на день (и `Enter` на дне в фокусе) — создание задачи со сроком этого дня:
  `CreateIssueModal` получает начальный срок (`openCreate({ dueDate })` в `store.tsx` рядом с `openCreateSubtask`;
  обычный «Создать» срок не наследует — как с родителем подзадачи).
- Сетка дней — `role="grid"` с `row`/`gridcell` (как у `DatePicker`), стрелки по дням, `PageUp`/`PageDown` — период,
  `T` — сегодня.

**Скорость**: 500 плашек в месяце не должны перерисовываться целиком при открытии задачи или перетаскивании — ячейка
дня `memo`, плашка получает стабильные пропсы (как `BoardColumn`, ADR-0011). Замер в PR: смена месяца и перетаскивание на
300 задачах, обе темы.

**Тесты**: раскладка (пур-функция `src/calendarLayout.ts`: дни периода, распределение задач по дням, «ещё N», неделя с
понедельника, переход через год) — юнит-тесты; вид — компонентный тест (данные по `dueFrom`/`dueTo`, перетаскивание
вызывает `updateIssue`, без права — не тащится, «+» открывает создание со сроком); роутер; горячие клавиши; `test:ui`
снимки календаря в обеих темах и axe без нарушений.

## J3. Дашборды — по проектам, Обзор — по задачам

Сейчас и дашборды организации, и Обзор проекта собраны из одних виджетов про задачи. Нужно: на уровне организации —
картина по **проектам**; в Обзоре проекта — его **задачи**.

**Новые виджеты** (закрытый список `DashboardWidget` в `contract.ts`, данные — `services/dashboardData.ts` под
`listVisibleProjects()`, как остальные; зеркало в `src/dashboards/spec.ts` + `spec.test.ts`; карточка в `catalog.ts`,
новая группа каталога «Проекты»):

| Тип | Что показывает | Данные |
|---|---|---|
| `projects` | таблица проектов: метка проекта, команда, доля закрытых (полоса), открытых, просроченных, целевая дата, **состояние** | `projects` + задачи (включая архив — как `progress`), `limit` 5–50 |
| `projectHealth` | сколько проектов в каждом состоянии, кольцом (`donut`) | то же правило |
| `milestones` | ближайшие вехи: дата, веха, проект; просроченные неотмеченные сверху | `project_milestones`, окно `periodDays` 7–180 вперёд |

**Состояние проекта** — одна функция на сервере (`services/projectHealth.ts`, юнит-тест на таблицу случаев), клиент
только показывает результат. «Сегодня» — `CURRENT_DATE` сервера:
1. «Завершён» — задачи есть, открытых нет;
2. «Просрочен» — целевая дата прошла, открытые есть;
3. «Под угрозой» — до целевой даты ≤ 14 дней и закрыто < 80 %, **или** просроченных ≥ 25 % открытых;
4. «По плану» — целевая дата есть, остальное не сработало;
5. «Без срока» — целевой даты нет (и не завершён).

Подписи состояний — словарь; цвет — токены `--status-*` (`Tag` из `ds`), плюс текст (не только цвет). Клик по проекту в таблице —
его Обзор; по вехе — «Сроки и вехи» проекта, если есть `editRoadmap`, иначе роадмап.

**Наборы по умолчанию**
- «Обзор организации» (`DEFAULT_ORG_OVERVIEW` в `catalog.ts`) — про проекты: `projectHealth`, `milestones`, `projects`
  во всю ширину, затем `progress`, `by-project`, `trend`. Сохранённые личные копии не трогать — это данные людей.
- Шаблоны нового дашборда (`DASHBOARD_TEMPLATES`): добавить «Портфель проектов» (те же виджеты), «Мои задачи» и «Команда»
  оставить.
- Обзор проекта (`DEFAULT_PROJECT_OVERVIEW`) — про задачи, как сейчас; добавить `milestones` этого проекта, если у
  проекта есть вехи (виджет на Обзоре ограничен проектом — как все виджеты Обзора).
- В каталоге «Добавить виджет» на Обзоре проекта **не** показывать `projects`, `projectHealth`, `by-project`, `progress` —
  в одном проекте они бессмысленны. Уже сохранённые обзоры с ними не ломать: они продолжают отрисовываться.

**Тесты**: сервер — данные трёх виджетов под видимостью (невидимый проект не попадает; один упавший виджет —
`{type:"error"}` только для себя), правило состояния; клиент — каталог Обзора без проектных виджетов, новый набор
«Обзора организации», `spec.test.ts`. Скорость — замер `server/scripts/performance-dashboard*.mjs` на 100 проектах /
50 000 задачах с новыми виджетами, запись в `docs/PERFORMANCE.md` «Дашборды»: виджет `projects` — один запрос с
группировкой, не запрос на проект.
