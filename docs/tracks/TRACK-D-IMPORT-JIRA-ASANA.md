# Трек D — импорт из Jira и Asana

**Исполнитель:** Codex. **Параллельно идёт трек E (английский интерфейс, делает Claude)** — см. раздел «Как не мешать
друг другу» внизу.

## Зачем

Сейчас в «Списке задач» есть только «Импорт из Trello». Команды, которые переходят на Taskira с Jira или Asana,
переносят задачи руками. Нужно, чтобы выгрузку из Jira и Asana можно было загрузить так же, как Trello: выбрать файл,
увидеть, сколько задач будет создано, нажать «Импортировать».

## Прочитать перед началом

1. `CLAUDE.md` — правила репозитория (команды, проверки, дизайн-токены, CSP, i18n, ADR). Он обязателен и для этого
   трека, хоть и называется так.
2. `CLAUDE.md`, раздел «Trello import is entirely client-side» — **главное решение, которое нужно повторить**, а не
   пересматривать.
3. `src/import/trello.ts` + `src/import/trello.test.ts` — образец разбора; в комментариях — пять раундов ревью с
   реальными ошибками (метки сверх лимита, коллизия усечённых меток, пустой срок `""`, пустое название).
4. `src/components/ImportTrelloModal.tsx` — окно импорта; `store.importIssues()` в `src/store/issueCrud.ts`.

## Решения, которые уже приняты (не менять)

- **Всё на клиенте, сервер не трогаем.** Никаких новых маршрутов, миграций, массового эндпоинта. Каждая задача
  создаётся через существующий `store.importIssues()` → `issuesApi.create()` → те же права и проверки, что у кнопки
  «Создать». Разбор — чистые функции без побочных эффектов, покрытые тестами.
- **Людей не сопоставляем.** Исполнитель и автор из Jira/Asana не переносятся: учётные записи двух систем не совпадают,
  а неверный исполнитель хуже, чем никакого.
- **Статусы не угадываем.** Статус Jira / секция Asana становится меткой `jira:<статус>` / `asana:<секция>`, задача
  создаётся в начальном статусе процесса — как список Trello сейчас.
- **Без новых зависимостей.** CSV разбираем своим маленьким парсером (корневой `package.json` сознательно урезан).
- **Никаких сырых цветов, `style=""`, капс-подписей** — проверки `colors:check`, `antilist:check` и CSP это ловят.

## Что сделать

### 1. Общий CSV-парсер — `src/import/csv.ts`

- RFC 4180: поля в кавычках, `""` внутри кавычек, перевод строки внутри поля, `\r\n` и `\n`, BOM в начале файла.
- Разделитель: запятая по умолчанию; если в строке заголовков нет запятых, но есть `;` — точка с запятой (Excel с
  русской локалью пересохраняет CSV именно так).
- Повторяющиеся заголовки сохраняются все: у Jira колонка `Labels` повторяется столько раз, сколько меток у самой
  «богатой» задачи. Удобный вид — `{ headers: string[]; rows: string[][] }` + помощник «все значения колонки по имени».
- Пустые строки в конце файла пропускаются.

### 2. Общий вид задачи импорта — `src/import/types.ts`

Вынести из `trello.ts` тип `TrelloImportItem` как `ImportItem` (`title`, `description`, `labels`, `dueDate`, `closed`)
и добавить `priorityId?: PriorityId` и `typeId?: IssueTypeId` (Trello их не задаёт — остаются по умолчанию).
Помощник метки источника с хэш-суффиксом (`trelloListLabel` сейчас) вынести в общий
`sourceLabel(prefix, name)`: Trello, Jira и Asana пользуются одним. **Тесты Trello должны пройти без изменений.**

### 3. Jira — `src/import/jira.ts`

Формат: Jira Cloud / Data Center, «Фильтр → Экспорт → CSV (все поля)» и «CSV (текущие поля)».

| Jira (колонка CSV) | Taskira |
|---|---|
| `Summary` | название (`sanitizeLine`; пустое — строка пропускается и считается в `skipped`) |
| `Description` | описание как есть (вики-разметку Jira не переводим) + в конце строка «Импортировано из Jira: KEY-12» (из `Issue key`) |
| `Issue Type` | `Bug` → `bug`; `Service Request`, `Request`, `Запрос` → `request`; остальное (`Task`, `Story`, `Epic`, `Sub-task`, …) → `task` |
| `Priority` | `Highest`, `Blocker` → `critical`; `High`, `Critical`, `Major` → `high`; `Medium` → `medium`; `Low`, `Lowest`, `Minor`, `Trivial` → `low`; неизвестное → `medium` |
| `Status` | метка `jira:<статус>` (через `sourceLabel`) |
| `Status Category` = `Done` **или** непустой `Resolution` | `closed: true` |
| все колонки `Labels` | метки (в пределах `LIMITS.labelsPerIssue`, место под `jira:<статус>` зарезервировано) |
| `Due Date` / `Due date` | срок `ГГГГ-ММ-ДД`. Jira пишет даты по-разному: `2026-09-29`, `29/Sep/26 12:00 PM`, `29.09.2026`, `9/29/2026` — разобрать эти четыре; нераспознанное → без срока и счётчик «сроков не распознано: N» в окне |
| `Parent`, `Parent id`, `Sprint`, `Assignee`, `Reporter` | не переносим; ключ родителя — в строку «Импортировано из Jira: KEY-12 (подзадача KEY-3)» |

Файл без колонки `Summary` — понятная ошибка «Файл не похож на CSV-выгрузку Jira — нет колонки Summary».
Названия колонок сравнивать без учёта регистра и пробелов по краям (у Jira на разных версиях `Due Date` и `Due date`).

### 4. Asana — `src/import/asana.ts`

Формат: Asana, «Проект → Экспорт/печать → CSV».

| Asana | Taskira |
|---|---|
| `Name` | название (пустое — пропуск, `skipped`) |
| `Notes` | описание + «Импортировано из Asana: <Task ID>» |
| `Section/Column` | метка `asana:<секция>` |
| `Tags` (через запятую в одной ячейке) | метки |
| `Due Date` (`ГГГГ-ММ-ДД`) | срок |
| непустой `Completed At` | `closed: true` |
| колонка `Priority` (пользовательское поле, если есть): `High`/`Medium`/`Low` | приоритет; нет колонки — `medium` |
| `Parent task`, `Assignee`, `Projects` | не переносим; имя родителя — в строку «Импортировано из Asana» |

Файл без колонки `Name` — ошибка «Файл не похож на CSV-выгрузку Asana — нет колонки Name».

### 5. Окно импорта

- `ImportTrelloModal.tsx` → общий `ImportModal.tsx` с выбором источника вверху: «Trello (JSON)», «Jira (CSV)»,
  «Asana (CSV)». Для каждого — своя короткая инструкция, где взять файл, и свой `accept` у поля файла.
- Остальное — как сейчас у Trello: сколько найдено, сколько пропущено без названия, флажок «включая закрытые» (для
  Jira/Asana закрытых по умолчанию не создаём), прогресс, отмена, итог «Импортировано N из M». Для Jira — ещё
  «сроков не распознано: N».
- Ограничение размера файла — 20 МБ, больше — понятное сообщение, файл не читается.
- Кнопка в шапке «Списка задач» называется «Импорт» и открывает это окно (права — `can("create")`, как сейчас).
- Окно — ленивый чанк, во входной бандл не попадает. Бюджет: `npm run build && npm run bundle:check`.
- Английская и русская версии всех строк — в `src/i18n/ru.ts` и `en.ts` (см. «Как не мешать друг другу»).

### 6. Тесты (обязательны — это и есть главная проверка трека)

- `csv.test.ts`: кавычки, `""`, перенос строки в поле, `\r\n`, BOM, `;`, повторяющиеся заголовки, хвостовые пустые строки.
- `jira.test.ts` и `asana.test.ts` на **рукописных** примерах выгрузок (`src/import/__fixtures__/`, 8–15 строк
  каждый) — настоящего аккаунта нет, поэтому примеры собрать по публичной документации и честно написать это в
  шапке файла, как в `trello.ts`. Покрыть: каждую строку таблиц сопоставления выше, пустое название, лишние метки
  сверх лимита, закрытые задачи, все четыре формата даты Jira и нераспознанную дату, «не тот файл».
- Тест окна: выбор источника, счётчики, флажок закрытых, вызов `importIssues` с правильными `CreateInput`.
- Существующие `trello.test.ts` — без изменений и зелёные.

## Как не мешать друг другу (трек E идёт параллельно)

- **Словари.** Оба трека правят `src/i18n/ru.ts` и `en.ts`. Все новые ключи трека D — одним блоком с префиксом
  `import.` в самом конце обоих файлов; старые `trello.*` не переименовывать (трек E их не трогает). Тогда при слиянии
  конфликт, если будет, — один непрерывный блок.
- **`Backlog.tsx`** — трогать только кнопку импорта и строку, которая открывает окно.
- **Не трогать** `IssueModal.tsx`, `DocsView.tsx`, `validation.ts`, `shared/permissions.matrix.json`, сервер —
  это территория трека E.
- Перед PR — `git merge origin/main` (не rebase), если трек E уже влит.
