# Taskira: результат внедрения аудита

**Дата:** 3 октября 2026. **Ветка:** `codex/design-audit-fixes`. Исходная версия — `a4df7b4`, после PR #122.

Внедрены изменения по всем 14 пунктам [исходного аудита](./REPORT.md), включая общий визуальный дизайн.
Собственная библиотека компонентов сохранена: найденные проблемы относились к поведению и композиции
экранов, а замена на UI-кит сама по себе их не устранила бы.

**Наглядное сравнение:** [до / после](./comparison.html). `screens/` — исходная версия,
`after/screens/` — собранная исправленная версия под production CSP. Все задачи и сотрудники синтетические.
Дизайн-решение зафиксировано в [ADR-0027](../../adr/0027-task-workspace-design.md).

## Что изменилось

| A08. Потеря фильтра | Поиск и условия доски/списка хранятся в URL и переходят между этими видами одного проекта. Общий компонент показывает применённые условия. Переход в другой проект сбрасывает их. | В fixture «Мои»: доска 3 → список 3; unit-проверки навигации и другой проект |
| A09. Плотность | Размеры задают токены DS. Compact уменьшает высоты и отступы, размер текста сохраняется. Мобильная область действия остаётся 44 px. | Desktop: обычная строка около 44 px, компактная 36 px; браузерная проверка фактической разницы |
| A10. Мелкие метаданные | Метаданные доски 12 px, у обычных плашек убраны повторяющиеся рамки. Просрочка сохраняет видимый семантический сигнал. Время и автор в задаче 12 px. | Скриншоты, контраст, обе темы |
| A11. Общий визуальный дизайн | Непрозрачная рабочая область, спокойные подложки колонок, одна граница карточки, меньше декоративных теней и градиентов. Общие радиусы и высоты. | A12. Мобильная карточка | Основные свойства перед описанием и лентой; дополнительные раскрываются отдельно. Подзадачи, чек-лист и вложения находятся рядом с описанием. | A13. Форма создания | Основные поля отдельно от чек-листа, направления, сложности и меток. Восстановленный черновик раскрывает заполненные дополнительные поля. Поля имеют доступные подписи. | Создание, восстановление, поиск исполнителя, направление, axe; обе темы |

Сохранённый пользователем набор колонок имеет приоритет над новой стандартной предустановкой.
Черновик хранится до окончания текущей сессии приложения и не переживает перезагрузку страницы.

## Проверки

- TypeScript: `npm run typecheck` — успешно.
- Все **716 модульных тестов** — успешно (`npm test -- --maxWorkers=3`). Ограничение параллельности
  позволило проверить набор без конкуренции браузеров за ресурсы машины.
- **27 браузерных проверок** нового поведения в dev: Chromium, Firefox, WebKit; светлая/тёмная темы,
  асинхронный поиск, клавиатура, черновики, фильтры, плотность, формы и мобильная компоновка.
- **27 проверок** этих рабочих сценариев на production-сборке в тех же трёх браузерах.
  После финального исправления мобильной сетки дополнительно прошли все **6** сценариев списка.
- Полный набор `npm run test:ui` в Linux — **105 из 105**. Обновлены 22 эталонных снимка DS;
  все 27 визуальных/клавиатурных проверок витрины прошли в составе полного набора. Версия Playwright 1.56.1 совпадает с CI.
- Отдельный production-набор CI в Linux — **36 из 36**.
- **36 регрессионных проверок** на production в Windows: шесть тем, брендовые оттенки, боковая панель,
  главная, мобильная доска, права наблюдателя, создание, персональный фон, загрузки и справка.
- Дополнительный сценарий CSP открывает задачу, раскрытые свойства, создание и выбор исполнителя
  под `style-src-attr 'none'`; собирает события `securitypolicyviolation`. Все 3 браузера прошли его без нарушений.
- **35 итоговых состояний** проверены axe, нарушений в них нет. Также axe входит в браузерные тесты форм.
- `colors:check`, `contrast:check`, `motion:check`, `antilist:check`, `docs:check`,
  `npm run build`, `bundle:check` — успешно.

Новые тесты: `e2e/design-audit.pw.ts`, `e2e/combobox-async.pw.ts`, `src/createDrafts.test.ts`,
`src/ds/Combobox.async.test.tsx`. В существующих проверках обновлены роли навигации и порядок раскрытия групп.
Проверка календаря ждёт загрузки трёх страниц из 300 задач до начала замера взаимодействий.
Фикстура API получила корректный пустой ответ личных задач, чтобы проверка главной не маскировала ошибку fixture.

## Размер и границы результата

Контрольная сборка `a4df7b4` — **347.77 КиБ gzip**, итог — **351.43 КиБ**, прирост **3.66 КиБ**.
Новые зависимости не добавлены. Допуск пересмотрен для этой реализации: total +156 КиБ, JS +142 КиБ
от исторической базы; лимиты entry/CSS сохранены. Причина и замеры — в [PERF-BUDGET](../PERF-BUDGET.md).
Tailwind сканирует шаблоны приложения, исторические классы из отчётов не увеличивают продуктовый CSS.
Механизм ограничения источников описан в [официальной документации Tailwind](https://tailwindcss.com/docs/detecting-classes-in-source-files).

Автоматические проверки не подтверждают полное соответствие WCAG и не заменяют NVDA/VoiceOver.
WebKit на Windows не заменяет Safari на реальном iPhone. Изменения композиции стоит оценить наблюдением
за сотрудниками на реальных задачах; повышение скорости работы и цели INP/FPS здесь не измерялись.
Backend, интеграция с рабочей БД и вычисления отчётов в эту реализацию не входили.

Сырые наблюдения: [до](./observations.json), [после](./after/observations.json).
Сводка команд, числа и размер сборки: [verification.json](./after/verification.json).

## Уточнение после проверки владельцем: панели и прозрачность

Длинные раскрывающиеся заголовки заменены общим WorkspaceControls: компактные кнопки сохраняют
размер, отдельная панель появляется ниже, одновременно открыта одна группа. Есть счётчик
фильтров, закрытие по Escape и кнопкой с возвратом фокуса. Настройки вида занимают ширину
содержимого; фильтры списка перестраиваются на узком экране. Включение выделения закрывает
панель и возвращает фокус, чтобы сразу перейти к задачам.

Чёрная область под настройками воспроизведена: фокус скрытого radio прокручивал внешний
лист приложения на 254 px, хотя прокручиваться должна только область настроек. У .ds-check
не было собственного containing block для absolute input. position: relative на подписи
удерживает native input в правильном scroll container. Исправление действует также для checkbox.
В том же сценарии main теперь заканчивается на y=892 при высоте окна 900, внешний лист не сдвигается.

Проверки: 716 модульных тестов; после последнего уточнения фокуса — повторные 48 тестов доски
и списка. Production suite — 52 сценария Chromium; новые панели и оформление — 32 сценария
Firefox/WebKit. Обе темы, ширины панелей 1440/390/320 и оформление 1654/390. Axe панелей —
без нарушений. Typecheck, build, bundle, colors, contrast, motion, antilist и docs проходят.
Размер JS+CSS — 351.89 КиБ gzip, в текущем бюджете; зависимости и лимиты не менялись.
