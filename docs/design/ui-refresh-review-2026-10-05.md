Дата: 2026-10-05.

- [Запрос Главной и совместимость истории](https://github.com/Bakhtovar-SA/Taskira/pull/133#discussion_r4183184220): проверены через `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` на локальной PostgreSQL 18. Сначала выбирается окно из 101 видимой открытой назначенной задачи; материализованный CTE ограничивает последующие обращения к истории этим окном. Предикат видимости, порядок приоритетов, сортировка и `truncated` сохранены. Новые индексы и миграции не требуются.
- [Обработка `/`, комментарий и выход](https://github.com/Bakhtovar-SA/Taskira/pull/133#discussion_r4183184545): ранний `return` перенесён внутрь ветки найденного поля, устаревший комментарий удалён. Выход остаётся в `UserMenu` общей панели. Шесть production-сценариев проверяют отчёты, общий и личный дашборд на 1440 и 390 px: открыть меню, POST logout, увидеть форму входа; ошибки JavaScript проверяются отдельно.
- [Статус `rework` и роль](https://github.com/Bakhtovar-SA/Taskira/pull/133#discussion_r4183184894): `rework` — необязательный sid пользовательского workflow, а не статус стандартного набора. Стандартный workflow использует серверный `returnedForRework`. Это только группировка отображения; правила `can()` и серверные разрешения не меняются. Тесты покрывают оба источника, отсутствие возврата и глобального администратора.

Старые записи переходов без `fromSid`/`toSid` возвращают `returnedForRework: false`.
По названию статуса прежний возврат не угадывается. Задачи остаются в группах
срочности или «Остальные», а явно заданный пользовательский `rework` поддерживается.
Добавлен серверный сценарий со 110 дополнительными назначенными задачами и старым
payload: возвращаются 100 задач, `truncated: true`, первым остаётся critical,
затем задача medium и самые новые low.

## Фокус календаря

Повторный Linux CI выявил перенос фокуса, отложенный на `requestAnimationFrame`.
Быстрый Enter мог выбрать прежний день; ожидание нового фокуса в тесте также
выявило сброс курсора после открытия. Инициализация календаря и перенос фокуса
теперь завершаются в `useLayoutEffect` вместе с отрисовкой сетки. Unit-регрессия
проверяет следующий день внутри месяца и переход 31 октября → 1 ноября без
выполнения отложенного кадра. Браузерный сценарий сохраняет выбор клавиатурой,
проверку диапазона и возврат фокуса после выбора и Escape.

Проверки: typecheck клиента и сервера, 14 unit-тестов Главной и две регрессии
DatePicker, девять серверных тестов Главной, шесть production-сценариев выхода и
шесть повторений браузерного сценария дат прошли. Production build и прежний
bundle budget проходят: JS + CSS gzip 352.26 КиБ при лимите 352.49 КиБ.

- [Поиск выбранных проектов](https://github.com/Bakhtovar-SA/Taskira/pull/133#discussion_r4183448978): список преобразуется в `Set` один раз; пересечение с видимостью сохраняется. Существующие проверки JSON и CSV покрывают недоступные и повторяющиеся id.

Это максимум 106 недельных точек. Добавлена проверка длинного периода CSV. Контракт использует календарь сессии PostgreSQL; он не обещает одинаковые недельные корзины при смене часового пояса БД. Проверка события около воскресенья/понедельника выполняет полный `buildReport()` в UTC, Asia/Tashkent и America/New_York: итоги совпадают с сериями, подписи остаются понедельниками, событие входит в соответствующую локальную неделю. Настройки production-БД не читаются и не изменяются; пояс явно описан в API README.
- [Стабильный порядок и индекс истории](https://github.com/Bakhtovar-SA/Taskira/pull/133#discussion_r4183449482): id добавлен к обоим `ORDER BY` Главной.
