# Проверка рабочего пространства Taskira

Дата: 11 ноября 2026. Проверялись локальные исходники и production-сборка; production-инсталляция не обновлялась.

## Реализованный объём

- Документы: Tiptap/Yjs/Hocuspocus в API, совместное редактирование, блочные комментарии, версии, восстановление, актуальность, вложения и явное создание задач из выделения.
- Объекты: типы реестров, семь типов полей, карточки, связи, фильтры, сортировка, история, архив и контроль конфликтов.
- Процессы: неизменяемые опубликованные версии, параллельные этапы, условия, проверяющий, доработка, пауза, отмена и транзакционные автоматизации с журналом и повтором ошибок.
- Планирование: независимые сценарии, нагрузка по сложности, зависимости, нормализация будущих этапов, 10 000 выборок, медиана/P80 и диапазон выполнения.
- Общая основа: проектные флаги и доступ, библиотека и поиск, обратные ссылки, история завершений, внутренний outbox, метрики и общий NDJSON-экспорт.
- Каталог файлов: все вложения задач и документов проекта, включая архивные источники; поиск, фильтры, сортировка, скачивание и переход к источнику. На узком экране — читаемые карточки файлов.
- Новые разделы следуют за исходными. Календари, флажки, загрузка, подтверждения и раскрытие оформлены компонентами Taskira; анимации и прокрутка учитывают reduced-motion. Исправлена потеря ссылки на документ при анимированной смене раздела.

Полный серверный прогон выполнен до последних небольших изменений общего экспорта и предельного размера документа;
эти изменения отдельно покрыты итоговым набором из 26 успешных проверок. C-локаль не использовалась для итоговой
регрессии: она не обеспечивает ожидаемое регистронезависимое сравнение кириллицы.

Браузерный набор проверяет создание и повторное открытие документа, запись в PostgreSQL, живую ссылку на задачу,
комментарии, таблицу без inline styles, опубликованный запуск, отложенные этапы, подтверждение результата,
недостаточную историю, прямые ссылки и обновление страницы. Проверены ширина рабочей области на 390 px,
светлая и тёмная темы, фокус, Escape/Enter и WCAG 2 A/AA через axe. Редактор отсутствует среди запросов доски.
Это автоматическая проверка выбранных экранов, а не полная сертификация доступности приложения.

Совместный редактор проверен двумя авторами и наблюдателем, с разрывом связи, накопленными правками,
перезапуском API и восстановлением версии. Отдельно синхронизирован документ примерно на 990 КБ с многобайтным текстом.
Размер бинарного состояния ограничен 1 000 000 байтами. Для документа используется отдельный
WebSocket-приёмник с лимитом 1 МиБ; канал `/api/ws` сохраняет лимит 8 КиБ актуального main.

## История клиентских проверок до интеграции main

`src/board.characterize.test.tsx:415` ожидает текст «БП» внутри аватара Бориса Петрова.
В текущих изменениях аватара отображается портрет, при этом доступное имя пользователя сохранено.
Этот сбой воспроизводится в полном наборе; изменения доски и аватаров уже присутствовали в рабочем дереве
до реализации модулей и сохранены. Тест не ослаблялся для получения зелёного результата.

В предыдущем полном прогоне 10 ноября дополнительно не дождался загрузки панели тест выделения двух карточек
(`src/board.characterize.test.tsx:557`). Отдельный повтор всего файла дал 18 passed / 1 failed:
панель выделения прошла, сбой инициалов остался. Предыдущие полные прогоны давали 887 passed / 1 failed.
Причина дополнительного сбоя при параллельной нагрузке не установлена; он не скрыт повторным успешным результатом.
Полный прогон 11 ноября дал 888 passed / 1 failed: тест панели выделения прошёл, сбой ожидания инициалов остался.
После добавления проверок настроек и справки итоговый полный прогон дал 893 passed / 1 failed с тем же сбоем аватара.

## Восстановление и закрытая поставка

На отдельных scratch-БД `taskira_test_workspace_backup*` выполнены `pg_dump -Fc` и `pg_restore`.
Файлы прошли штатные `ops-storage export`, `verify` и `import` в новый пустой каталог.
Сверены все строки 21 таблицы через детерминированные хэши, бинарное состояние документа,
контрольная версия, подтверждение актуальности и SHA-256 вложения. Рабочая БД не использовалась.

Контейнеры клиента и API собраны успешно в локальные теги `taskira-workspace-check:client` и
`taskira-workspace-check:server`. Первоначальный запуск исходных Dockerfile остановился в npm из-за
недоверенного сертификата корпоративного TLS-прокси (`SELF_SIGNED_CERT_IN_CHAIN`). Для проверки
созданы временные копии Dockerfile с подключением доверенного CA только к шагам `npm ci` через
BuildKit secret и `NODE_EXTRA_CA_CERTS`. Проверка TLS не отключалась; сертификат не сохранялся
в runtime-образах. Исходные Dockerfile проекта не изменялись. При сборке в этой же сети нужно
обеспечить доверие корпоративному CA на стороне среды сборки.
Полный production-архив релиза и установка на закрытый сервер в этой проверке не выполнялись.
Существующий mock-набор `scripts/test-release-scripts.sh` прошёл в Linux с GNU awk и в Windows Git Bash: проверены
сборка архива с имитацией образов, манифесты, контрольные суммы и включение новых инструкций и референса.
Shell-файлы для Linux запускались из отдельной копии с LF; исходное рабочее дерево сохраняет свои окончания строк.
Новые зависимости входят в npm lockfiles и образы; новый внешний сервис не требуется.

## Включение

После штатного обновления API миграция применяется автоматически. Документы, объекты, процессы и планирование выключены по умолчанию. Каталог файлов включён,
чтобы сохранить доступность уже существующих вложений.
Менеджер или администратор включает их в **Настройки проекта → Модули**.
Начните с проверочной копии проекта и сценария из [WORKSPACE](../../WORKSPACE.md).
При выключении сохраняются чтение и экспорт; новые изменения, этапы и правила останавливаются.

Локальные протоколы запуска сохранены в `D:/Taskira/reports/workspace-*.log`;
скриншоты браузерной приёмки — в `test-results/`. Команды повторения приведены в [README](README.md).
