# Движение (motion): рабочий документ

Живой документ: где в продукте есть движение, как оно устроено, как его добавлять и что открыто. Решение — в
[ADR-0035](../adr/0035-motion-library-spike.md); оно принято и не правится, а этот файл обновляется с каждым изменением
движения. Правила ТЗ 5.13 проверяет `npm run motion:check` (`scripts/check-motion.mjs`).

## Как устроено

- **Одна точка входа — `src/motion.ts`.** Библиотека `motion/mini` (`animate` + `spring`) живёт ленивым чанком
  `src/motionEngine.ts` (~5 КБ gzip) и импортируется только оттуда. `motion/react`, `AnimatePresence`, `layout`,
  `animateView` не используются (ADR-0035 п. 3: CSP, размер, `secure-jsx`).
- **Только WAAPI и CSSOM** (`el.animate`, `el.style.x`, `setProperty`): CSP `style-src-attr 'none'` запрещает `style=""` и
  `<style>` (ADR-0010). Значения, которые меняются каждый кадр, ставят через `ref={cssVars({...})}` или атрибут `data-*`.
- **Пока чанк не загружен — мгновенно**, без «догоняющих» анимаций; грузится на простое (`preloadMotionIdle`).
- **Reduce-motion** проверяет сама обёртка: `motionReduced()` — единая точка истины для JS (системный
  `prefers-reduced-motion` или личный выключатель «Уменьшить движение» в «Профиль → Внешний вид», он ставит `data-motion="reduce"` на `<html>`). Библиотека reduce не учитывает. CSS-анимации гасятся теми же правилами
  под `@media (prefers-reduced-motion: reduce)`; `motion:check` ловит анимацию без такого правила.
- **Длительности** — токены `--dur-1…5`, не дольше 450 мс; пружины — именованные пресеты `SPRING*` в обёртке
  (полное время успокоения ≤ 500 мс).

## Что есть в обёртке

| Функция | Что делает |
|---|---|
| `flipFrom(el, left, top, {lift})` | FLIP одного элемента: из прежней точки пружиной; прерванное движение продолжается с видимого места |
| `enter(el, kind)` / `exit(el, kind)` | появление (opacity + подъём, `rise`/`toast`/`dialog`/`panel`/`pop`) и уход (200 мс, узел снимает вызывающий) |
| `glideTo(el, box)` / `glideWidth(el, from, to)` | перелёт индикатора вкладок; ширина сайдбара |
| `flash(el)` | подсветка поля при смене значения (только цвет фона) |
| `viewTransition(update)` | перекрёстное затухание смены экрана (свой, не `animateView`) |
| `stopMotion(el)` | снять текущую анимацию элемента |
| `preloadMotion()` / `preloadMotionIdle()` | загрузка чанка |
| `motionReduced()` / `setReducedMotion()` | единая точка reduce-motion |

## Где применено

Доска (`boardFlip.ts`: FLIP переноса, новая карточка), тосты, `Dialog`/`SidePanel`/палитра, вкладки (`ds/Tabs.tsx`),
список задач и «Входящие» (`listEnter.ts` — вход; `listExit.ts` — уход), сайдбар (ширина), меню/поповеры
(`--ease-spring`), чекбоксы и радио, чек-лист, бейджи и колокольчик (`usePulse`), смена экрана (`anim-view`), дашборды и
«Отчёты» (`anim-stagger`, линии графиков).

Сознательно **не** анимируется: полосы таймлайна и роудмапа (виртуализация), смена месяца в календаре (ломает фокус),
«язычок» сайдбара, ошибки операций (встряска — вестибулярный риск), перетаскивание (нативный DnD, ADR-0007).

## Как добавить движение

1. Нужно ли оно? Движение должно объяснять изменение (элемент появился/ушёл/переехал), не украшать.
2. Только transform/opacity (и цвет фона для подсветки); не размеры, не `top/left`, не `backdrop-filter`.
3. Через функции обёртки; новая функция — в `src/motion.ts`, и она сама учитывает `motionReduced()` (мгновенный итог, без кадров).
4. Много элементов — порог (как `MAX_TRACKED` в `listExit.ts`/`boardFlip.ts`): выше — мгновенно (VDI).
5. После анимации не должно оставаться inline-стиля, который перебьёт классы (`track()` снимает `clear`-свойства).
6. Фокус и порядок чтения не должны страдать; движение не должно менять итоговую раскладку (e2e меряют её).
7. Тест: unit (вызов, reduce, прерывание) и, где есть раскладка/фокус, e2e в настоящем Chromium.

## Прерывание и повторный вход

Новая анимация положения или ширины того же элемента продолжает с видимого состояния: `flipFrom` использует
снимок видимого положения у вызывающего, `glideTo` читает текущий transform, `glideWidth` замеряет
`getBoundingClientRect().width / cssZoom(el)` до отмены предыдущей анимации. Поэтому быстрые повторные переключения
сайдбара продолжают движение с текущей ширины.

Повторный `enter` во время движения пропускается: уже начавшийся вход не возвращает opacity/transform к первому кадру.
После завершения и очистки `finished` следующий вход разрешён. Уход имеет приоритет: `exit` перехватывает вход;
`Dialog` перед CSS-уходом вызывает `stopMotion`, который отменяет движение и снимает его inline-кадр.
Cleanup прежней анимации не стирает кадр новой. Смена reduce-настройки запрещает новые анимации,
уже начавшиеся могут доиграть.

`npm run motion:check` · `npm run colors:check` · `npm run bundle:check` (ленивый чанк считается в `js`/`total`; запас

(`e2e/`; `ui-visual` в CI на PR, трогающих компоненты).

## Открыто

Список исправлений, проверок и идей — в треке O (`docs/tracks/TRACK-O-MOTION-WAVE2.md`). Известные
ограничения доски: снимок положений — один слот на модуль, при нескольких одновременных переносах полностью
анимируется последний. У одиночного переноса снимок живёт `TTL_MS` (3 с) от броска: если сервер подтверждает дольше,
карточка проиграет вход вместо посадки. У массовой операции после ответа сервера окно продлевается на `RENEW_AHEAD_MS`
(итого ≈ 10 с, `renewBoardFlip` в `boardFlip.ts`), и снимок закрывается после первого коммита с переездом.
