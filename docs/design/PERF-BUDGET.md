  простое (`requestIdleCallback` / при наведении на карточку) и шаги 3–4 ADR-0011; выбрать при реализации.

  запасной `setTimeout`) и при `pointerenter`/`focus` карточки; `lazy()` остаётся, в начальный бандл чанки не
  входят. Проверен и вариант «не рендерить через `lazy()`, если модуль уже загружен» — первое открытие 65 мс, как
  и с обычным `lazy()` после предзагрузки, поэтому оставлен простой вариант. Разница «первое ≈ 380 / повторное
  ≈ 85 мс» до правки — ожидание чанка плюс торможение раскрытия Suspense после показа фолбэка (≈ 300 мс в React);
  с загруженным модулем фолбэк не показывается. Шаги 3–4 ADR-0011 для этой цели на 1× уже не нужны.
- **п. 5.** На карточках доски ключ задачи набран JetBrains Mono (ADR-0012 п. 5), поэтому первый экран доски тянет
  третий файл. Экран входа и главная не замерялись (на главной в «Моих задачах» тоже есть ключи). Решение за
  владельцем трека: либо цель «≤ 2» относится только к экрану входа, либо ключи на доске переходят на табличные цифры Onest
  (моно остаётся в карточке задачи), либо моно сабсетится и встраивается в Onest-файл. Пока — зафиксированное
  нарушение.

### Проверка в CI

`scripts/check-bundle-size.mjs` (`npm run bundle:check`) читает `dist/assets/*.js|*.css`, сжимает каждый файл gzip,
считает JS, CSS, JS+CSS и входной чанк (скрипт из `dist/index.html`) и сравнивает с `base + allowedGrowth` из
`scripts/bundle-budget.json`; превышение любой метрики — код выхода 1. В `.github/workflows/test.yml` (job `client`)
шаг идёт сразу после `npm run build`.

Мутационная проверка (25.09.2026):
- входной чанк: `base.entry` уменьшена на 1 КБ, допуск 0.5 КБ → «входной чанк = 79.14 KB > 78.64 KB», код 1;
- рост бандла: в `dist/assets` добавлен несжимаемый чанк на 96 КБ gzip → «JS + CSS = 292.94 KB > 276.49 KB» и
  «JS, все чанки = 279.54 KB > 263.09 KB», код 1; при +64 КБ — в пределах, код 0;
- после отката — код 0.

Ловушка, найденная при замере базы: Tailwind v4 сам ищет классы во **всех** файлах репозитория, включая `docs/*.md`
и тесты. Упоминание at-правила контейнерного запроса (слово container с «собакой» впереди) в документации добавило в
production CSS одноимённую утилиту (+16 байт gzip; здесь оно намеренно не написано буквально); классы в тестовых стендах — тоже. Бюджет такое ловит, если рост заметный; мелочь видна в выводе
как ненулевой рост CSS при неизменённом коде.

Как менять базу: `node scripts/check-bundle-size.mjs --update` переписывает `base` текущими размерами. Делать это
только вместе с правкой этого документа (новая точка отсчёта — новое решение), не чтобы «пройти CI».

## Как мерить

01.10.2026 владелец согласовал треку J ещё 10 КБ общего JS и JS+CSS:
допустимый рост от базы теперь 140 и 150 КБ соответственно. Лимиты CSS и входного чанка прежние.
Календарь загружается лениво (3,80 КБ gzip JS и 0,74 КБ CSS); проверка — `npm run bundle:check`.

| что | команда | где цифры |
|---|---|---|
| бандл | `npm run build && npm run bundle:check` | вывод + `scripts/bundle-budget.json` |
| перерисовки (jsdom, число компонентов) | `npm run perf:rerenders` | таблицы в выводе, ADR-0011 |
| кадры, открытие задачи, шрифты, CSP (браузер) | `npm run build`, затем `SPIKE_NODE_MODULES=… CHROMIUM_PATH=… node scripts/perf-board/run.mjs` (шапка файла) | JSON в выводе |
| CSP-механизмы стилей | `SPIKE_NODE_MODULES=… npm run csp:spike` | таблица в выводе, ADR-0010 |

`perf:rerenders` идёт и в обычном `npm test` — без порогов, только «замер состоялся»: цифры видны, но улучшение или
ухудшение CI не роняет. Порог на число перерисовок имеет смысл ввести после шагов 0–2 ADR-0011, когда цифра станет
стабильной и маленькой. Шаги 0–2 выполнены 25.09.2026 (цифры выше стабильны между прогонами); порог в тест пока не
внесён — отдельное решение владельца трека.

03.10.2026 владелец согласовал ещё 1 КБ общего JS+CSS для брендового фавикона (PR #121):
допустимый рост total от базы — 151 КБ. Фавикон добавил около 0,5 КБ gzip;
лимиты JS, CSS и входного чанка сохраняются.
