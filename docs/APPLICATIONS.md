# Приложения Taskira

Taskira разделяет рабочие задачи, документы и реестры на три приложения. У каждого своё меню;
учётная запись, проекты и ссылки на материалы общие. Эта поставка остаётся одной установкой
Taskira с одним API и PostgreSQL. Отдельные сервисы, «Обращения» и «Студия» пока не создаются.
Причины решения — [ADR-0038](adr/0038-application-suite.md).

## Что открывать

| Приложение | Для чего | Основная навигация |
|---|---|---|
| **Работа** | Создать и выполнить задачу, организовать последовательность работы, оценить план | Входящие, мои задачи, проекты и представления задач; процессы, планирование и файлы проекта |
| **Знания** | Подготовить инструкцию, совместно написать документ, найти актуальную редакцию | Главная приложения, библиотека, документы и файлы проекта |
| **Объекты** | Найти систему, оборудование, договор или другую запись и историю работы с ней | Главная приложения, библиотека, реестры и файлы проекта |

Переключатель рядом со знаком Taskira меняет приложение. В меню проекта остаются только
представления выбранного приложения. Создание обычной задачи находится в «Работе»;
контекстные действия из документа и объекта сохраняют связь с источником.

Библиотека собирает исходные материалы доступных проектов, а **Файлы** собирают вложения
задач и документов выбранного проекта. Переключение приложения не копирует материалы и
не меняет их владельца. Полная страница задачи открывается в «Работе»; панель задачи
поверх документа или реестра сохраняет выбранное приложение. Ссылки на документ и объект
ведут в соответствующее приложение.

## Подключение и права

Есть два уровня настройки:

1. **Организация → Приложения**: глобальный администратор подключает «Работу», «Знания»
   и «Объекты» для всей установки. Хотя бы одно приложение должно оставаться включённым.
2. **Настройки проекта → Модули**: проект сохраняет свои переключатели спринтов,
   документов, объектов, процессов, планирования и файлов и прежние права их настройки.

При обновлении все три приложения подключены, чтобы действующие разделы продолжили работу.
Существующие флаги проектов не меняются: документы, объекты, процессы и планирование
изначально выключены для нового проекта; файлы включены. Поэтому обычный проект с задачами
не получает пустые разделы документов или реестров после обновления. Если нужен только
трекер задач, администратор может оставить подключённой одну «Работу».

Доступность приложения не даёт доступа к проекту. Сервер по-прежнему проверяет членство и
роль при каждом действии. Приглашение к отдельной задаче не открывает связанные материалы
проекта. Переключатель показывает проекты, доступные текущему пользователю и имеющие
соответствующий модуль или сохранённые материалы. У «Работы» доступны видимые пользователю
проекты; у «Знаний» — проекты с включёнными документами или существующим документом;
у «Объектов» — с включённым реестром или существующей записью.

Отключение приложения сохраняет разрешённое чтение, прямые ссылки и экспорт. Сервер
запрещает новые изменения принадлежащих ему материалов; фоновые процессы также учитывают
подключение. Например, при отключённой «Работе» документ можно прочитать, но создать из
него задачу нельзя. Отключённые «Знания» переводят совместные документы в чтение.
Принятые до отключения изменения редактора сохраняются на сервере. Включение возвращает
работу с существующими данными; паузы процессов требуют явного возобновления.

## Адреса и запоминание выбора

Прежние адреса продолжают работать:

- `/p/CORP/board` и `/p/CORP/issue/CORP-123` — «Работа»;
- `/p/CORP/documents?document=…` — «Знания»;
- `/p/CORP/objects?object=…` — «Объекты»;
- `/apps/work`, `/apps/knowledge`, `/apps/objects` — главные страницы приложений.

Явный адрес важнее запомненного выбора: закладка, ссылка из уведомления, обновление страницы,
«Назад» и «Вперёд» открывают указанный контекст. При обычном переключении используется
последний доступный проект этого приложения либо первый доступный проект; при отсутствии
проектов показывается главная приложения с объяснением. Предпочтения интерфейса сохраняются
локально отдельно для каждой учётной записи. После выхода другой пользователь не получает
чужой выбор приложения и проекта. Содержимое документов и токены в этих настройках не хранятся.

Если подключение или доступ отозван, старое предпочтение не возвращает возможность изменения.
Прямая ссылка на сохранённый материал остаётся способом разрешённого чтения, а приложение
снова проверяет актуальные права на сервере.

## Пример: проверка корпоративного портала

1. Анна открывает **Объекты**, выбирает «Корпоративный портал» и видит владельца,
   инструкцию и предыдущую проверку.
2. По ссылке на инструкцию она попадает в **Знания**, проверяет версию и актуальность.
3. Проверка выполняется через процесс и задачи в **Работе**. Михаил получает задачу
   со ссылками на портал и инструкцию, выполняет её и прикладывает протокол.
4. Результаты проверки команда дополняет в документе. Замечание превращается в задачу
   только после явного подтверждения создания; ссылка на исходный раздел сохраняется.
5. Анна возвращается к карточке портала и находит результат, задачи и историю. В **Файлах**
   проекта доступен протокол, загруженный в задачу, вместе с вложениями документов.

У каждой роли остаётся понятное место работы. Контекст передаётся через ссылки, а данные
и проектные права сохраняются. Полное описание документов, реестров и процессов —
[в руководстве рабочего пространства](WORKSPACE.md).

## Контракт и сопровождение

`GET /api/applications` требует пользовательскую сессию и возвращает:

```json
{
  "revision": 1,
  "canManage": true,
  "applications": [
    { "id": "work", "enabled": true, "projectIds": ["project-id"] },
    { "id": "knowledge", "enabled": true, "projectIds": [] },
    { "id": "objects", "enabled": true, "projectIds": [] }
  ]
}
```

`PATCH /api/applications` доступен глобальному администратору через сессию. API-токены
не управляют установкой. Запрос передаёт текущую ревизию и полный набор переключателей:

```json
{
  "revision": 1,
  "enabled": { "work": true, "knowledge": false, "objects": false }
}
```

Устаревшая ревизия возвращает `409`: нужно перечитать настройку, проверить изменения другого
администратора и повторить выбранное действие. Выключение всех приложений не допускается.
`enabled` отражает подключение для установки; `projectIds` — видимые пользователю проекты
для приложения, в том числе с материалами для чтения после отключения. Эти сведения не
заменяют серверную проверку конкретного материала.

Настройки подключения хранятся в PostgreSQL и входят в обычный бэкап БД; вложения остаются
в существующем файловом хранилище. Нового облачного сервиса и отдельного комплекта секретов
нет. Документный редактор загружается отдельным чанком при открытии документа. Проверки
доступа и ограничений CSP, резервного копирования и восстановления сохраняются.

## Приёмочные проверки

Клиентские проверки навигации, предпочтений, контроллера и Справки:

```bash
npm test -- --run src/applications/navigation.test.ts src/store/applicationPreferences.test.ts src/store/applications.test.tsx src/components/DocsView.test.tsx
```

`e2e/application-shell.pw.ts` проверяет установку только с «Работой», переключение меню,
прямые ссылки и историю браузера, работу только со «Знаниями», отзыв доступности открытого
редактора, административные переключатели, смену учётной записи, клавиатуру, узкий экран,
тёмную тему и доступность. Он запускается вместе с прежними сценариями рабочего пространства:

```bash
npm run build
npx playwright test --config playwright.workspace.config.ts
```

Для этого набора нужен отдельный `DATABASE_URL_TEST` с именем БД, начинающимся с
`taskira_test_workspace_e2e`. Фикстура пересоздаёт тестовые данные; локальный демонстрационный
стенд или рабочую БД использовать нельзя. `PLAYWRIGHT_PORT` позволяет выбрать свободный
порт production-preview, не останавливая другой локальный стенд.
