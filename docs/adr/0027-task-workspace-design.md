# ADR-0027 — Спокойная рабочая область, общая плотность и семантика переключателей

**Статус:** Accepted
**Дата:** 2026-10-03
**Supersedes:** ADR-0016 и ADR-0023 (частично: прозрачность рабочего листа); уточняет ADR-0014

## Контекст

Аудит версии `a4df7b4` после PR #122 обнаружил недостаток места для названий, перегруженные мобильные инструменты,
одинаковую высоту строк в двух плотностях и ошибки сценариев поверх собственной библиотеки компонентов.
Визуальная оценка показала конкуренцию рамок, стеклянных поверхностей и плашек с содержанием задач.
Владелец попросил реализовать результаты аудита, включая общий визуальный дизайн.

## Решение

1. Сохранить собственную DS, Manrope, брендовый акцент и семантические цвета статусов. Замена библиотеки
   не устраняет найденные проблемы композиции и интеграции. Новые зависимости не нужны.
2. Рабочий лист `.glass-sheet` использует непрозрачный `--bg-canvas` в обеих темах. Боковая панель,
   небольшие плавающие поверхности и персональные фоны сохраняют свои роли из ADR-0023.
   Колонки доски используют спокойную подложку, карточки — одну границу без декоративного градиента.
3. Плотность определяется токенами DS: comfortable — высоты контролов 32/36/40 и строка 44 px;
   compact — 28/32/36 и строка 36 px. Размер текста сохраняется. На телефонах рабочие действия
   имеют область 44 px, строки списка показывают двухстрочное название, статус, исполнителя и меню.
4. Название — основное содержимое списка. Стандартные колонки: приоритет, срок, статус, исполнитель.
   Метки и направление доступны в настройках. Минимальная ширина названия 320 px на компьютере;
   на промежуточных ширинах таблица прокручивается внутри рабочей области.
5. Поиск доступен сразу; фильтры и настройки раскрываются группами, активные условия остаются видимыми.
   Доска и список одного проекта сохраняют общие условия через URL. Переход в другой проект их сбрасывает.
6. В форме создания основные поля отделены от дополнительных. Черновики живут только в памяти текущей
   сессии, раздельно по пользователю, проекту и родителю. Закрытие сохраняет ввод; успешный ответ сервера
   или явное удаление очищает его. Logout/401 очищает все черновики и запрещает поздние записи старой сессии.
7. Мобильная карточка показывает основные свойства перед описанием, подзадачами и лентой. Дополнительные
   свойства раскрываются отдельно. DOM следует мобильному порядку, desktop располагает свойства справа.
8. `Tabs` разделяет семантику: навигация — ссылки с `aria-current`; фильтры — кнопки с `aria-pressed`;
   настоящие вкладки — `tablist/tab` со связью `aria-controls` с панелью. Название задачи в списке — ссылка.
   Асинхронный Combobox разрешает выбор только из ответа на текущую строку поиска.

## Последствия

- Для рабочих задач больше места и меньше одновременно видимых инструментов. Скрытые свойства требуют
  одного раскрытия; их доступность и активные условия должны проверяться на реальных экранах.
- Черновик защищает от случайного закрытия и сетевой ошибки, но не переживает перезагрузку страницы.
  Это сознательный срок хранения без записи содержания задач в браузерное хранилище.
- Изменения визуальной иерархии — экспертное решение, не доказательство ускорения работы пользователей.
  Для оценки результата требуется наблюдение за реальными сценариями.
- Нативные примитивы и CSP остаются основой. Проверки сценариев в Chromium, Firefox и WebKit дополняют
  витрину DS; WebKit на Windows не заменяет проверку Safari/iOS, а axe — проверку скринридером.
