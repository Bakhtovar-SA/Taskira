# ADR-0005 — Двухслойная модель прав: глобальная роль + роль в проекте

**Статус:** Accepted
**Дата:** 2026-09-06

## Контекст

Изначально роль доступа была одной глобальной колонкой `users.access_role`: один человек не мог быть менеджером в своём
проекте и наблюдателем в чужом. `SCOPE.md` требует, чтобы роль назначалась в рамках проекта. Продукт многоотдельный:
у каждого департамента свои проекты.

## Решение

Два слоя (`ROLE_MIGRATION.md` §3): **глобальная роль** `users.global_role IN ('admin','member')` — уровень ресурса
(создаёт департаменты, проекты, пользователей; неявно полные права в любом проекте; держится ≥ 1 активный `admin`) и
**проектная роль** `project_members.role IN ('manager','employee','viewer')`. Эффективная роль для матрицы =
`resolveRole`: `admin` для глобального админа, иначе проектная роль, иначе нет доступа. Матрица `MATRIX` от проекта не
зависит; `editWorkflow` и `manageAccess` остаются только у `admin`. У `employee` право `edit` сужено до задач, где он
исполнитель или автор. Миграции `004` (проектные роли) и `006` (удаление `access_role`).

## Последствия

- Сервер авторитетен; клиентская копия матрицы только для подсказок UI (позже вынесена в единый источник — ADR-0001).
- Управление составом проекта — только у глобального `admin`; менеджер проекта состав не правит.
- Кросс-департаментные проекты, несколько проектов на департамент и project-level кастомные роли вынесены за рамки
  этого решения.
