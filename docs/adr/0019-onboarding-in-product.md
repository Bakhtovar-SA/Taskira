# ADR-0019 — Онбординг встроен в продукт: прогресс на сервере, шаги отмечают реальные действия

**Статус:** Accepted
**Дата:** 2026-09-27

## Контекст

ТЗ 5.11: новый человек должен понять Taskira без документации и без звонка владельцу. Онбординга не было вообще.
ТЗ прямо запрещает пошаговые модальные туры с затемнением и повторный показ подсказок после закрытия. Нужны:
первичная настройка администратора, «Начало работы» участника, понятный вход гостя, пустые состояния и
подсказки при первой встрече с функцией, плюс демо-проект, который удаляется без следов.

## Решение

1. **Прогресс — на сервере, по пользователю** (`user_onboarding`, миграция `20260927T1800_onboarding.sql`):
   шаги «Начала работы», флаг «скрыть навсегда», id закрытых подсказок. Не `localStorage` — иначе на втором
   устройстве всё начнётся заново, а ТЗ требует «не показывать повторно».
2. **Шаги отмечает сервер от реальных действий** — маршруты после успеха вызывают `markStep()`
   (`services/onboarding.ts`): открыл задачу, где он исполнитель; сменил статус; оставил комментарий; сохранил
   уведомления. Клиент сообщает только шаг «тема» — тема живёт в браузере, сервер её не видит. Отметка
   никогда не роняет само действие и кэшируется в процессе, чтобы горячие маршруты не ходили в БД повторно.
3. **Первичная настройка — страница, а не тур**: раздел «Организация → Начальная настройка» (`/admin/setup`).
   Первый вход администратора после установки открывает её один раз за сессию, пока `instance.setup_completed_at`
   пуст; уже работающие инсталляции миграция считает настроенными.
4. **Демо-проект** (`projects.is_demo`, не больше одного — частичный уникальный индекс) создаётся одной
   транзакцией напрямую, без маршрутов задач: без уведомлений и без `audit_log`. Удаление снимает проект
   (каскады FK) и строки `audit_log`, появившиеся от работы с демо-задачами. Это сознательное исключение из
   правила «всё административное — в аудит»: ТЗ требует, чтобы после удаления в БД не осталось строк, и тест
   это проверяет по всем таблицам. Прогресс онбординга самого администратора — не данные демо и остаётся.
5. **Гость** (приглашён в отдельные задачи) видит в своей оболочке, где он и что может.
6. **Подсказки** — одна строка в интерфейсе (`<Hint id>`), закрывается и не возвращается; работу не блокирует.

## Последствия

- Онбординг не зависит от браузера и честно отражает, что человек уже сделал, а не что он «прокликал».
- Каждый новый шаг — правка закрытого списка `ONBOARDING_STEPS` и одного маршрута; шаги без серверного
  следа (как тема) требуют явного вызова с клиента.
- Удаление демо не оставляет следа в журнале аудита — если такой след понадобится, это новое решение.
- Проверка ТЗ «администратор доходит до рабочего проекта меньше чем за 5 минут» — на человеке со стороны,
  не автоматическим тестом.
