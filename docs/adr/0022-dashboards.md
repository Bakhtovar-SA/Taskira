# ADR-0022 — Дашборды: виджеты из закрытого списка, данные под видимостью смотрящего, своя сетка и свои графики

**Статус:** Superseded by ADR-0033 (частично)
**Дата:** 2026-09-29

## Контекст

Нужны дашборды: сводная картина по проектам организации и по одному проекту без похода в отчёты и списки. В
продукте уже есть отчёты (`/reports`, сводка за период) и главная («Мои задачи»), но нет собираемого из блоков экрана.
Требования владельца: личные и общие дашборды, вкладка «Обзор» у проекта, отчёты — первым встроенным дашбордом,
никаких новых зависимостей ради графиков и сетки, дизайн — в рамках DESIGN.md.

## Решение

1. **Одна таблица `dashboards`** (миграция `20260929T1000_dashboards.sql`): название, владелец, `project_id`
   (NULL — уровень организации), `shared`, `widgets jsonb`. Три вида:
   - **личный** (`shared = false`, без проекта) — видит и правит только владелец;
   - **общий организации** (`shared = true`, без проекта) — видят все, создаёт и правит глобальный администратор;
   - **обзор проекта** (`project_id` задан) — не больше одного на проект (частичный уникальный индекс), видят все, кому
     виден проект, правят по новому праву **`manageDashboards`** (admin, manager) из матрицы. Пока обзор не сохранён,
     показывается встроенный набор виджетов из кода; «Сбросить» удаляет строку и возвращает встроенный.
2. **Виджеты — данные, не код**: закрытый список типов (`count`, `breakdown`, `trend`, `issues`, `workload`,
   `progress`, `activity`), у каждого — схема zod в `contract.ts`. Позиция в сетке (x, y, w, h) хранится в самом
   виджете. Сервер проверяет границы сетки и уникальность id; наложение виджетов не запрещает — порядок строк задаёт
   клиент при раскладке.
3. **Данные — одним запросом под видимостью того, кто смотрит**: `POST /api/dashboards/data` принимает список
   виджетов (сохранённых или ещё не сохранённых — для предпросмотра) и считает каждый на проектах из
   `listVisibleProjects()`, как отчёты. Общий дашборд не раскрывает ничего сверх того, что человек и так видит:
   виджет с невидимым проектом возвращает пустые данные, а не ошибку. На обзоре проекта область всех виджетов
   принудительно сужается до этого проекта. Ошибка одного виджета не валит остальные.
4. **Отчёты не переписываются**: раздел «Дашборды» показывает их первым встроенным пунктом, ведущим на `/reports`.
5. **Клиент без библиотек**: сетка — CSS Grid на 12 колонок, позиции через `cssVars` (CSP, ADR-0010); перенос и
   изменение размера — нативный drag-and-drop и указатель, с клавиатурной альтернативой (стрелки двигают, Shift+стрелки
   меняют размер). Графики (кольцо, столбики, линии тренда) — свои SVG-компоненты на токенах цвета; каждый график
   дублируется текстом или таблицей для скринридера.

## Последствия

- Новый тип виджета = схема в `contract.ts` + расчёт в `services/dashboardData.ts` + компонент на клиенте; хранимые
  данные при этом не мигрируют. Неизвестный тип при чтении старой строки отбрасывается, а не ломает дашборд.
- Разрешения на общий дашборд организации — только у глобального администратора; отдельной роли «аналитик» нет.
- Отправка данных виджетов по расписанию (письмом) и виджеты по пользовательским полям в эту версию не входят.
