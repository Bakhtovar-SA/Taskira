# ADR-0013 — Информационная архитектура: навигация, три дома настроек, просмотр задачи

**Статус:** Accepted
**Дата:** 2026-09-25

## Контекст

ТЗ 5.6 трека 5 v2. Инвентаризация (`docs/design/INVENTORY.md`, карты 3 и 4) показала: участники проекта
настраиваются в двух местах, настройки проекта разнесены по «Департаментам» и «Рабочему процессу», личные
настройки есть только в меню аватара и не на всех экранах, десяток серверных функций (лицензия, обслуживание,
пользователи, проверка LDAP, аудит, предупреждения здоровья) не имеет интерфейса, клавиши 7 и 9 открывают скрытые
экраны-отказы, гость живёт в отдельной ветке логики без настроек. Черновик структуры и серые вайрфреймы
(`docs/design/IA.md`) показаны владельцу 25.09.2026.

## Решение

Владелец утвердил все пять пунктов гейта (`IA.md` §9) с уточнениями:

1. **Боковая панель** (§2.1): знак и название инсталляции; «Поиск и команды» (Ctrl K) и «Новая задача»; личный
   слой — Главная, Входящие, Мои задачи, Приглашения (если есть); Избранное; **Проекты** — раздел-дерево:
   отдел → проект → представления проекта (Доска, Список, Таймлайн, Спринты при включённом модуле); у каждого
   уровня свой отступ и направляющая линия, чтобы вложенность читалась без подписей; клик по проекту раскрывает его
   представления. «Организация» — Роадмап, Отчёты; внизу Справка, Настройки, профиль. Представления текущего
   проекта дублируются вкладками в шапке проекта.
2. **Три дома настроек** (§3): Личные (`/settings/…`), Проект (`/p/:key/settings/…`), Организация (`/admin/…`).
   У каждой настройки один дом; в других местах — только ссылки. Участники проекта — только в «Доступе» проекта.
   Значения, которые задаются только env, показываются справочно.
3. **Просмотр задачи** (§4): панель справа с Доски и Списка (адрес `?issue=KEY`), полная страница по
   `/p/:key/issue/:issueKey`, из Входящих и Моих задач. Модалка уходит. `J`/`K` — соседние задачи.
4. **Адреса** (§5): новые пути и редиректы со всех старых. Главная есть всегда; при одном проекте после входа
   сразу открывается он.
5. **Клавиши** (§7): `1`–`4` — только представления проекта; переходы — `G` + буква; `?` — справка.

Уточнение владельца: **не уходить от утверждённого вида** (ADR-0016) — структура меняется, язык дизайна нет.

**Открытый вопрос — дашборды.** Владелец хочет дашборды, место не определено. Функции нет в продукте и в
треке, поэтому в этот ADR она не входит (ТЗ 5.6 запрещает добавлять функции). Рекомендация на момент решения:
раздел «Организация → Дашборды», где нынешние «Отчёты» становятся первым встроенным дашбордом, а проектный
дашборд — ещё одна вкладка представления проекта. Записано в `docs/design/IDEAS.md`; решение — отдельным ADR,
когда появится ТЗ.

## Последствия

- ТЗ 5.8 (оболочка) и 5.9 (настройки) реализуются по этому ADR; `IA.md` — подробная спецификация.
- Старые пути (`/p/:key/backlog|workflow|access|admin|docs|collaborating`) должны редиректить; ссылки
  `/p/:key/issue/:key` не ломаются, но открывают полную страницу вместо модалки.
- Клавиши `5`–`9` перестают открывать экраны: это изменение привычки для тех, кто ими пользовался.
- Гостевой режим (`bootStatus = solo`) сводится к тому же личному слою без проектов.
