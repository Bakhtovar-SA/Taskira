# ADR-0006 — «Эпик» — обычная задача; в интерфейсе — «Направление»

**Статус:** Accepted
**Дата:** 2026-09-05 (типы задач); 2026-09-08 (термин в интерфейсе)

## Контекст

Продукт должен быть удобен всем отделам без жаргона разработчиков; «Epic» — Jira-сленг. Типы `story` и `epic`
дублировали общий тип `task` и вносили жёсткую иерархию, которая нетехническим отделам не нужна.

## Решение

1. Типы задач сводятся к `task | bug | request` (миграция `002_corporate.sql`, 2026-09-05): `story` и `epic` слиты в
   `task`. Группировка сохраняется как ссылка на другую задачу — nullable `issues.epic_id` (плюс поля таймлайна
   `t_start`/`t_span`, `color`). «Эпик» — это обычная задача, на которую ссылаются.
2. В интерфейсе термин — «Направление» (решение D2 в `UI_RESTRUCTURE.md`, 2026-09-08): только подписи и тексты. Поле
   `epicId` в контракте API и БД **не переименовывается** — ломающее изменение ради косметики отклонено.

## Последствия

- Иерархия эпиков без жёстких сроков и глубины; отдельного типа `epic` нет.
- Расхождение терминов: в UI «Направление», в коде и API `epic*` — осознанно.
- Подзадачи (`parent_id`, миграция 021) — отдельное понятие, независимое от направления.
