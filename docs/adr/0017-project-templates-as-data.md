# ADR-0017 — Шаблоны проектов — данные над существующими настройками, а не флаги возможностей

**Статус:** Accepted
**Дата:** 2026-09-27

## Контекст

ТЗ 5.10 трека 5 v2: «разные оболочки под разных клиентов» (уровень Б) — проект «под свои нужды» за минуту.
Альтернатива — модель возможностей проекта (`ProjectCapabilities`, CLAUDE.md о спринтах): разные наборы экранов и
поведения по флагам. Она дорогая (каждый флаг — ветка в клиенте и сервере) и ТЗ её прямо запрещает.

До этого у проекта всегда были четыре статуса `todo / inprogress / review / done`: граф в «Процессе» рисовался по
заготовленным координатам этих `sid`, «Сбросить схему» ставила 8 стандартных переходов по ним же.

## Решение

1. Шаблон проекта — **спецификация из уже существующих настроек**: статусы и переходы, пользовательские поля,
   шаблоны задач, представление по умолчанию, предложенные метки, модуль спринтов. Схема — `ProjectTemplateSpec`
   (zod, `contract.ts`), тип выводится.
2. Встроенные шаблоны (5) — `server/src/templates/builtin.json`, проверяются схемой при загрузке модуля; шаблоны
   организации — таблица `project_templates` (jsonb), проверка при сохранении.
3. Применение — внутри транзакции `POST /api/projects` вместе с участниками: при любом сбое проекта нет.
4. **Статусы проекта больше не обязаны быть четырьмя стандартными**: у проекта из шаблона свои `sid`
   (`draft`, `legal`, …) и категории. Граф процесса раскладывает незнакомые `sid` по категориям; сброс схемы к
   стандартной у такого проекта недоступен (`409`) — иначе он остался бы без переходов.
5. Две новые настройки проекта, которые задаёт шаблон: `projects.default_view` (с какого представления открывать)
   и `projects.suggested_labels` (подсказки при вводе, не ограничение). Expand-миграция `20260927T1000`.
6. «Сохранить проект как шаблон» — новое право `saveProjectTemplate` в матрице (роль `admin` в проекте есть только
   у глобального администратора).

## Последствия

- Никаких флагов и разных наборов экранов: проект из шаблона — обычный проект, всё меняется в его настройках.
- Код, который полагается на стандартные `sid`, должен работать и без них (перевод названий статусов в
  `workflowStatus.ts` уже падает обратно на имя из БД).
- Иконка и цвет проекта, фон проекта (шаги 2 и 4 мастера в ТЗ) — таких настроек у проекта нет; значок проекта
  по-прежнему выводится из ключа. Добавлять их — отдельное решение, не часть шаблонов.
