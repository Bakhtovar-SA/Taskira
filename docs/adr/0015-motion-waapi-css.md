# ADR-0015 — Движение: CSS + Web Animations API + View Transitions, без библиотеки

**Статус:** Accepted
**Дата:** 2026-09-25

## Контекст

ТЗ 5.13 требует выбрать инструмент для движения: WAAPI + CSS + своя маленькая утилита против библиотеки
(например, Motion). Ограничения на момент решения:

- CSP `style-src-attr 'none'`: инлайн-стили в разметке запрещены; CSSOM-записи, `setProperty` и WAAPI
  (`el.animate`) разрешены — проверено в Chromium (ADR-0010, `npm run csp:spike`).
- Бюджет бандла 5.2 (`scripts/bundle-budget.json`): входной чанк ~80 KB gzip, запас на весь трек 40 KB.
  Motion — порядка 15–30 KB gzip в зависимости от набора функций.
- Эталонная машина — Intel i3-N305; всё, что роняет кадры на ней, не делаем.
- Правила трека: длительности только из токенов, ничего дольше 450 мс, кроме заставки; любая анимация
  прерывается новым действием; при reduced-motion — мгновенно или только прозрачность.

Уже используется: CSS-анимации состояний (`anim-*` в `index.css`, `--dur-*`/`--ease-*` в `tokens.css`),
нативный HTML5 DnD (ADR-0007).

## Решение

Библиотеку движения не подключаем. Слои из ТЗ 5.13 закрываются так:

1. **Состояния компонентов** — CSS-переходы на токенах `--dur-1…5`, `--ease-*`.
2. **Навигация** — View Transitions API там, где она есть; без неё — мгновенно. Первое применение —
   смена темы: новая тема раскрывается кругом от точки нажатия, 420 мс, клип анимирует WAAPI на
   `::view-transition-new(root)` (`src/theme.ts`); правила псевдоэлементов ограничены классом `vt-theme`
   на время перехода.
3. **Раскладка** — FLIP своей утилитой на WAAPI (First/Last через `getBoundingClientRect`, Invert/Play
   через `el.animate`), когда понадобится перестановка в списке/колонке.
4. **Обратная связь** — CSS-классы (`anim-drop`, `anim-toast`, …).
5. **Перетаскивание** — нативный DnD (ADR-0007) + `setDragImage` со своим «призраком» карточки и
   силуэтом на исходном месте через DOM-атрибут `data-dragging`, без состояния React
   (`Board.tsx` `setDragGhost`).

Значения, зависящие от данных (координаты, радиус), передаются только через CSSOM/WAAPI, не через `style=""`.

## Последствия

- Ноль килобайт на движок движения; всё прерываемо браузером (новый `startViewTransition` отменяет прежний,
  WAAPI-анимации отменяются `cancel()`).
- Без View Transitions (старые Safari/Firefox из матрицы `docs/design/BROWSERS.md`) переходы навигации
  просто мгновенные — это допустимый запасной вариант по ТЗ 5.13.
- Пружинной физики и оркестрации «из коробки» нет; если понадобится сложная хореография (кроме заставки),
  это новый ADR с замером бюджета.
- Каждый новый анимированный переход обязан уважать `prefers-reduced-motion` сам (в `index.css` —
  общий блок `@media (prefers-reduced-motion: reduce)`, в JS — проверка `matchMedia`).
