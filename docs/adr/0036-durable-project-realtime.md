# ADR-0036: Долговечная синхронизация проекта и безопасные черновики

**Статус:** Accepted
**Дата:** 2026-11-02

## Контекст

WebSocket доставлял только сигнал персональных уведомлений. Изменения задач
других участников оставались невидимыми до обновления страницы. Нужны
восстановление после разрыва, сохранность черновиков и проверка конкурентных
сохранений. Счётчик sequence в транзакции записи не задаёт порядок COMMIT:
более поздний номер может стать видимым раньше предыдущего.

## Решение

- Триггеры задач, связанных записей и метаданных создают транзакционную
  очередь `realtime_pending`, независимо от наличия вебхуков.
- Диспетчер после COMMIT под общим advisory lock переносит зафиксированные
  изменения в `realtime_events`. Только эта последовательность становится
  клиентским курсором; незавершённые транзакции не могут потеряться за курсором.
- Подписка WebSocket ограничена одним проектом и перед доставкой проверяет
  актуальную сессию и доступ. HTTP `/sync` читает тот же журнал и обеспечивает
  резервную сверку. Доставка допускает повторы, чтение с курсора идемпотентно.
- История хранится семь дней с очисткой префикса последовательности. При
  истёкшем или опережающем курсоре, большом отставании или изменении метаданных
  клиент сверяет текущее состояние через `reset:true`.
- Клиент объединяет события, не применяет устаревший снимок поверх локальной
  записи, сохраняет текст редактора и позицию списка. Периодическая сверка
  повторяет также запросы представлений, не завершившиеся после подтверждения
  курсора. Устаревшие записи получают 409 по `expectedVersion`/`expectedValue`.

## Последствия

Обновление устанавливается в порядке миграция → сервер → клиент. Нет новых
внешних сервисов или зависимостей. Отдельные таблицы журнала увеличивают запись
в PostgreSQL; размер и возраст очереди доступны в Prometheus.

ADR-0024 остаётся в силе: поддерживается один serving API на БД. Координация
диспетчера через БД не делает остальные кеши и push уведомлений распределёнными.
Офлайн-записи, присутствие участников и посимвольное совместное редактирование
в это решение не входят. Протокол и проверки: [REALTIME](../REALTIME.md).
