# ADR-0003 — Спринты — опциональный модуль проекта, выключен по умолчанию

**Статус:** Accepted
**Дата:** 2026-09-15
**Supersedes:** ADR-0002 (частично: только для проектов с флагом `sprintsEnabled`)

## Контекст

Решение ADR-0002 удалило спринты целиком, обоснованно: они были мёртвой функциональностью. Появилась новая бизнес-цель,
которой на момент ADR-0002 не было: отдельно предоставляемый (продаваемый) Agile-модуль для конкретных проектов — первый
шаг плана на переключаемые возможности проекта (`ProjectCapabilities`: спринты, WIP-лимиты, режим оценки, раскладка
доски, словарь терминов) поверх одной модели данных.

## Решение

Спринты возвращаются как **опциональный модуль, выключенный по умолчанию**: флаг `projects.sprints_enabled`, миграция
`023_sprints.sql`. Все маршруты `/sprints*` и `PATCH …/issues/:id/sprint` отвечают 404, если флаг выключен, независимо
от роли. Право `manageSprints` (`admin`, `manager`) восстановлено под тем же именем. Не более одного активного спринта
на проект гарантирует БД (частичный уникальный индекс). Завершение спринта переносит незакрытые задачи в бэклог одной
транзакцией. Полная модель `ProjectCapabilities` не строится — заложена одна точка расширения.

## Последствия

- Проекты без флага не изменились: решение ADR-0002 остаётся в силе для них.
- Не сделано и не планируется этим решением: burndown/velocity, Scrum-церемонии, встраивание в общий workflow.
- Цена: снова есть таблица, право и три маршрута, которые надо держать 404-защищёнными по флагу.
