# ADR-0002 — Спринты удалены из базового продукта

**Статус:** Superseded by ADR-0003 (частично: для проектов с включённым модулем; для остальных решение остаётся в силе)
**Дата:** 2026-09-08

## Контекст

`SCOPE.md` с самого начала относил «спринты, scrum-церемонии, оценку в story points» к «осознанно откладываем / не
делаем», при этом в коде жили таблица `sprints`, `issues.sprint_id`, право `manageSprints`, три роута и весь экран
`Backlog.tsx` из секций спринтов. На dev-БД реального планирования не было — только дефолтный seed-спринт на проект.
Продукт рассчитан на несколько отделов (ИБ, HR, бухгалтерия, разработка) без узкого Jira-сленга.

## Решение

Спринты удаляются целиком, без «надгробия» (решение D1 в `UI_RESTRUCTURE.md`): миграция `012_drop_sprints.sql`
(`DROP COLUMN issues.sprint_id`, `DROP TABLE sprints`), право `manageSprints` убирается из `MATRIX` в обеих копиях
`permissions.ts`, «Бэклог» становится плоским «Списком задач» с фильтрами и сортировкой. Дамп `sprints` не делается.

## Последствия

- Миграция необратима (как `006`): данные спринтов и привязки задач теряются.
- Удаление права — снятие возможности, а не переназначение прав, поэтому «замороженной матрицы» из ROLE_MIGRATION не
  касается; матрица менялась в обеих копиях одним коммитом.
- Планирование в спринтах в базовом продукте недоступно. Позже для отдельных проектов вернулось как опциональный
  модуль — см. ADR-0003.

## Источники

`server/migrations/012_drop_sprints.sql` (коммит `fa6a256`, 2026-09-08); `UI_RESTRUCTURE.md` D1; `SCOPE.md`.
