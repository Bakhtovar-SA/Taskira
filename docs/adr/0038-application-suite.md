# ADR-0038: Самостоятельные приложения над общей установкой Taskira

Status: Accepted

Date: 2026-11-11

## Контекст

В Taskira появились документы, реестры объектов, процессы и планирование (ADR-0037).
Добавление каждого направления в одно меню проекта увеличивает число решений при входе.
Пользователю нужен понятный рабочий контекст, а организации — возможность подключать только
необходимые приложения. При этом действующие проектные права, ссылки на материалы и закрытая
поставка должны сохраняться.

Разделение интерфейса и выделение независимо разворачиваемых сервисов решают разные задачи.
Текущая установка использует один обслуживающий API на БД (ADR-0024), общую cookie-сессию,
внутренние события и совместное редактирование. Отдельное развёртывание каждого приложения
сейчас добавило бы распределённые транзакции, отзыв доступа между процессами и новые
операционные требования без необходимости для пользовательского разделения.

## Решение

Ввести три самостоятельных пользовательских приложения с общим переключателем:

- **Работа**: задачи и их представления, спринты, процессы, планирование и показатели.
- **Знания**: документы, совместное редактирование, версии и актуальность.
- **Объекты**: реестры, карточки и связанная с объектами история работы.

Каждое приложение показывает собственную навигацию. Общими остаются учётная запись,
проектные границы доступа, поиск, уведомления, файлы и ссылки на исходные материалы.
Существующие URL сохраняются; явная прямая ссылка определяет открываемое приложение.
Локальные предпочтения выбора интерфейса относятся к конкретной учётной записи и не
предоставляют права. Настройка недоступного приложения не может восстановить к нему доступ.

Глобальный администратор управляет подключением приложений для установки. Проектные флаги
продолжают определять включённые возможности внутри проекта. Два уровня не заменяют
проектную авторизацию: установка приложения сама по себе не открывает ни одного проекта.
Отключение останавливает новые действия и сохраняет разрешённое чтение и экспорт ранее
созданных материалов. Вложения остаются у исходной задачи или документа.

На первом этапе сохраняется одна SPA-поставка, один API-процесс и одна PostgreSQL БД.
Каталог приложений и проверка их доступности имеют отдельный серверный модуль и типизированный
контракт. Проектные API и владение данными сохраняются. Новые границы развиваются через
явные контракты; отдельные процессы и БД не создаются этой поставкой.

## Последствия

Пользователь сначала выбирает вид работы и видит соответствующие действия. Организация может
внедрять приложения постепенно, сохраняя ссылки и историю. Отключение требует серверной
проверки, включая фоновые процессы и открытые совместные редакторы; скрытия пункта меню
недостаточно.

Приложения используют общую дизайн-систему и ограничения CSP. Редактор документов продолжает
загружаться лениво и не входит в стартовую загрузку «Работы». Проверки должны покрывать
прямые ссылки, историю браузера, смену учётной записи, отзыв доступности и обе темы.

Независимое масштабирование, обновление или изоляция сбоев могут стать основанием для
следующего ADR о выделении сервиса. Для него потребуются отдельные решения о транзакциях,
доставке событий, авторизации, совместном редактировании и резервном копировании.
«Обращения» и «Студия» не входят в эту поставку.
