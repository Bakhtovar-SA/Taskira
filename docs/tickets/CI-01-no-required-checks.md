# CI-01 — ни один CI-чек не обязателен: весь CI без ручной дисциплины декоративный

**Статус: открыт, приоритет высокий до показа покупателю.** Найдено 2026-09-21 при попытке сделать джобу `types`
обязательной (см. UI-02).

- **Факт:** `gh api repos/Bakhtovar-SA/Taskira/branches/main/protection` и `/rulesets` отвечают 403 «Upgrade to
  GitHub Pro or make this repository public». На текущем тарифе приватного репозитория нельзя включить защиту ветки,
  а значит и required status checks — **ни для одной** джобы (`tests`, `server`, `client`, `ldap`, `security`,
  `migration-policy`, `types` и др.), не только для `types`. Красный чек не мешает мержу; сегодня их держит только
  привычка не мержить красное.
- **Почему важно:** для B2B-продукта «мерж только при зелёных проверках» — минимальное ожидание покупателя; заявления
  в `docs/SECURITY_OVERVIEW.md` о проверках CI опираются на то, что их нельзя обойти.
- **Варианты:** (1) тариф GitHub с защитой веток/rulesets для приватных репозиториев (или публичный репозиторий) и
  required checks на `main`; (2) если тариф не меняется — гейт вне GitHub: pre-push/pre-merge хук, сервисная ветка-
  «страж» с автоматическим мержем только при зелёном `tests`, либо проверка статусов в скрипте релиза
  (`build-release.sh`) перед тегом; (3) как минимум — правило в процессе и запись об этом в SECURITY_OVERVIEW.
- **Не сделано:** ничего из вариантов не включено; запись в SECURITY_OVERVIEW не менялась.
