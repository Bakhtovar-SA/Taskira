# SEC-RATE-01 — лимиты на чувствительные действия

**Статус: открыт, в работе на ветке `claude/m-sec-rate-01`.** **Severity: medium.** Тикет Трека M ([TRACK-M-PRODUCTION-READINESS.md](../tracks/TRACK-M-PRODUCTION-READINESS.md), раздел M1 «SEC-RATE-01»); здесь — только привязка к строкам самопроверки SEC-ASVS-01 ([docs/security/ASVS-L2.md](../security/ASVS-L2.md)). Объём, критерии и порядок работ — в треке, этот файл их не переопределяет.

- **Требования:** ASVS 5.0: V2.4.1 (сводная таблица лимитов из этого тикета закрывает и часть V2.1.3 вместе с [SEC-DOC-01](SEC-DOC-01-security-documentation-gaps.md)).
- **Факт (по самопроверке, код `main` на `4b2736d`):**
  - Есть: общий лимит 600 запросов/мин на пользователя или токен (`server/src/app.ts:110-137`), лимит входа по IP и блокировка аккаунта (`routes/auth.ts:25-53`), `inFlight`-лимит расчёта дашбордов (`routes/dashboards.ts:57`).
  - Нет отдельных лимитов на экспорт данных и аудита, CSV-отчёты, поиск, ручной повтор вебхука, создание API-токена (кроме лимита числа активных токенов), ручной запуск повторяющихся правил.
- **Решение:** чинить до внешнего аудита — по плану Трека M (SEC-EXT-01 идёт после SEC-RATE-01), работа уже идёт.
- **Что сделать:** по Треку M — таблица «маршрут → лимит → ключ (user/ip) → где реализовано» в SECURITY_OVERVIEW и тесты на 429; лимитер в рамках ADR-0024.
- **Критерий готовности:** по Треку M; после слияния строки V2.4.1 и V2.1.3 в ASVS-L2.md пересмотрены.
- **Не сделано (на `main`):** ничего из перечисленного.
