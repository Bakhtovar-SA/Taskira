# SEC-CACHE-01 — ответы API без `Cache-Control`, данные в `localStorage` после выхода

**Статус: открыт.** **Severity: low.** Найдено в SEC-ASVS-01 (самопроверка ASVS 5.0 L2, 2026-10-06; [docs/security/ASVS-L2.md](../security/ASVS-L2.md)).

- **Требования:** ASVS 5.0: V14.3.1, V14.3.2, V14.3.3.
- **Факт:**
  - `Cache-Control: no-store` выставлен только для вложений, CSV-отчётов и токенов (`routes/attachments.ts:81`, `routes/reports.ts:136`, `routes/apiTokens.ts:10`); прочие JSON-ответы API — без заголовка.
  - `taskira.recentIssues` (ключ и название последних задач) не очищается при выходе и не привязан к пользователю (`src/palette/recent.ts:14-30`); `Clear-Site-Data` не отправляется.
- **Почему важно:** на общей рабочей станции следующий пользователь увидит названия задач предыдущего; промежуточные кэши могут сохранить ответы API.
- **Что сделать:**
  1. Fastify `onSend`: `Cache-Control: no-store` для всех `/api/*`, кроме явных исключений (аватарки/логотип/фото проекта с `immutable`).
  2. При выходе и при смене пользователя очищать `taskira.recentIssues` (и любые данные организации в `localStorage`); при желании `Clear-Site-Data: "storage"` в ответе `/auth/logout`.
- **Критерий готовности:** тест: ответ `GET /api/auth/me` и списка задач содержит `no-store`; клиентский тест — после выхода палитра пуста.
- **Не сделано:** ничего из перечисленного.
