# SEC-JWT-01 — алгоритм JWT не закреплён, проверка подписи и срока не покрыта тестами

**Статус: открыт.** **Severity: low.** Найдено в SEC-ASVS-01 (самопроверка ASVS 5.0 L2, 2026-10-06; [docs/security/ASVS-L2.md](../security/ASVS-L2.md)).

- **Требования:** ASVS 5.0: V9.1.1, V9.1.2, V9.2.1.
- **Факт:**
  - `app.register(jwt, { secret })` без `verify.algorithms` (`app.ts:105`); проба 2026-10-06: HS512-подпись тем же секретом принимается, `alg=none` и подмена payload отвергаются, просроченный токен отвергается (401). Поведение — библиотеки, не нашей конфигурации.
  - Автотестов на подделку, `alg=none`, смену алгоритма и истёкший `exp` нет.
- **Почему важно:** требование «allowlist алгоритмов» должно быть в конфигурации и под тестом, а не следствием версии библиотеки.
- **Что сделать:**
  1. `sign: { algorithm: "HS256" }`, `verify: { algorithms: ["HS256"], extractToken: requestToken }`.
  2. Тесты в `server/test/security.auth.test.ts`: подмена payload, `alg=none`, HS512, просроченный токен, токен с неверным `sessionVersion`.
- **Критерий готовности:** тесты зелёные; строки V9.1.1, V9.1.2, V9.2.1 в ASVS-L2.md ссылаются на них.
- **Не сделано:** ничего из перечисленного.
