# ROUTE-03 — массовые операции (ТЗ 3.3) реализованы только в Backlog.tsx, не в Board.tsx

**Статус: открыт, не блокирует ничего.** Найдено при реализации ТЗ 3.3 (план v2 Трек 3),
2026-09-22.

- **Что сделано:** `PATCH /api/projects/:id/issues/bulk` (status/assignee/priority/delete,
  частичный успех по каждой задаче) — на сервере полностью, применимо к любому виду. UI
  (чекбоксы в режиме выделения, панель действий, отчёт результата) — только в `Backlog.tsx`
  («Список задач»): плоский список строк, чекбокс на каждой — прямолинейная UI-задача.
- **Почему не в Board.tsx тоже:** выделение карточек на канбан-доске — отдельная UI-задача
  (карточки в колонках, а не строки списка; нужно решить, как ведёт себя чекбокс поверх
  drag&drop одной карточки — `ADR-0007` уже фиксирует, что доска использует нативный HTML5
  drag&drop, и режим выделения не должен с ним конфликтовать), не просто "переиспользовать тот
  же JSX". Контекст исходного ТЗ P0-5 явно упоминал оба (`Board.tsx`, `Backlog.tsx`).
- **Не блокирует:** сервер уже один на оба вида — `issuesApi.bulk()` и
  `store.bulkApplyIssueAction()` (`src/store/issueCrud.ts`) переиспользуются как есть, когда
  дойдёт очередь до Board.tsx; тесты на сервер и на сам стор уже покрывают это независимо от UI.
- **Проверка после реализации:** выделение карточек на доске (в т.ч. из разных колонок),
  применение одного из четырёх действий, отчёт результата — тот же, что уже есть в
  `Backlog.tsx`; ручная проверка, что режим выделения не ломает drag&drop одиночной карточки.
