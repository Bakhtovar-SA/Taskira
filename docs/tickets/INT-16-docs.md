# INT-16 — Документация трека L

**Трек:** [L](../tracks/TRACK-L-INTEGRATIONS.md) · **ADR:** 0028–0031 · **Зависит от:** INT-01…INT-15 (все влиты) · **Блокирует:** —

## Цель

Документы описывают реальное поведение после трека: эксплуатация, безопасность, архитектурная памятка, справка в
продукте.

## Задание

1. **`CLAUDE.md`** — раздел «Integrations (track L)» после «Server structure», 15–25 строк:
   - outbox на триггерах (`integration_events`); правило «событие существует тогда и только тогда, когда есть
     строка истории или комментарий»; склейка по транзакции; новое событие = новый член `ActivityEvent`;
   - задания `webhook-dispatch` / `due-events` / `recurring` на `startJob`;
   - SSRF-allowlist в env; `secretBox` и `WEBHOOK_SECRET_KEY`;
   - токены: `tsk_`, `requireSession` против `requireAuth`, запрет токенам в `requireGlobalAdmin`; сервисные записи
     (`auth_source='service'`) не получают уведомлений и не предлагаются в выборе людей;
   - повторяющиеся задачи: `createIssueInTx`, уникальность `(rule_id, scheduled_for)`, одна догоняющая;
   - `ops_runs` пишут скрипты хоста, `GET /api/admin/status`.

   В «Gotchas» — экстренное отключение триггеров (`ALTER TABLE … DISABLE TRIGGER`).
2. **`docs/OPERATIONS.md`**:
   - «Вебхуки»: включение, формат `WEBHOOK_ALLOWED_TARGETS` с примерами, `WEBHOOK_DENY_CIDRS`, генерация
     `WEBHOOK_SECRET_KEY` (`openssl rand -hex 32`) и хранение рядом с `JWT_SECRET`, что будет при восстановлении без
     ключа (подписки `secret_unavailable` → сменить секрет), экстренное отключение (env и триггеры);
   - правила оповещения Prometheus из трека L §8;
   - «Повторяющиеся задачи»: `RECURRING_ENABLED`, пояс;
   - «Экран состояния»: что означает каждая проверка и её пороги;
   - «Регулярная репетиция» (из INT-13), если ещё не полностью.
3. **`docs/SECURITY_OVERVIEW.md`**:
   - «Сеть»: исходящие вебхуки только на цели из allowlist оператора, проверка каждой попытки, без редиректов и
     прокси, подпись HMAC, тонкое тело;
   - «Аутентификация»: API-токены — срок, scope, хеш, запрет административных маршрутов, сервисные записи;
   - «Полнота экспорта»: строки таблицы из трека L §3.5;
   - «Данные и шифрование»: `WEBHOOK_SECRET_KEY` вне бэкапа.
4. **`docs/design/IA.md`** §3 — строки разделов «Интеграции», «Повторяющиеся», «API-токены», «Сервисные записи» в
   таблицах трёх домов; «Состояние системы» — новое содержание.
5. **Справка `DocsView`** (RU и EN, одинаковые разделы — проверяет `DocsView.test.tsx`):
   - «Повторяющиеся задачи» (`#recurring`);
   - «API-токены» (`#tokens`) с примером `curl`;
   - «Интеграции и вебхуки» (`#webhooks`) с форматом тела, заголовками и кодом проверки подписи из трека L §5;
   - «Резервные копии» (`#backup`) — ссылка на эксплуатацию и смысл карточек экрана состояния.

   Якоря совпадают со ссылками INT-15. Если `DocsView` ещё не прокручивает к разделу по `location.hash`
   (сейчас разделы имеют `id` с префиксом, переход — кнопкой), добавить: при монтировании и на `hashchange`
   вызвать существующий `go(id)` для `#<id>`; тест в `DocsView.test.tsx`.
6. **`server/README.md`** — в оглавление/обзор: «Интеграции» со ссылками на разделы тикетов; таблица env-переменных.
7. **`DOCKER_SETUP.md`** — новые переменные и их значения по умолчанию.

## Критерии приёмки

- В корне `npm run typecheck && npm test && npm run build && npm run docs:check && npm run permissions:check` — зелёно.
- Ссылки в изменённых Markdown-файлах ведут на существующие файлы и якоря (проверка ревьюером; при наличии в CI —
  линкчекер).
- `SECURITY_OVERVIEW.md` не обещает ничего, чего нет в коде: каждое утверждение раздела «Сеть» и «Аутентификация»
  ссылается на тикет и тест, который его проверяет (список — в описании PR).
