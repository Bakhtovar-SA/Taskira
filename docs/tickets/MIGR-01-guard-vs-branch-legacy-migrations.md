# MIGR-01 — `check-migrations.sh` красный против `main` на миграциях 028/029

**Статус:** открыт, не блокирует PERF-06. Записан, чтобы не потеряться при слиянии в `main`.

`scripts/check-migrations.sh main` на ветке `codex/perf-00-indexed-pages` падает:
`new migration must use YYYYMMDDTHHMM_name.sql: 028_notify_email_mandatory.sql, 029_session_version.sql`.
Против `3d57b29` (база последней проверки) — чисто.

**Причина (проверено):** это не чужие коммиты в `main`. `main` заканчивается на `024`; `028`/`029`
добавлены коммитом `4ecf23d` (#53) в других ветках (`codex/*`) и попали сюда вместе с ними. Для
охранника они «новые относительно `main`», а по `docs/MIGRATIONS.md` номера `001`–`029` — легаси
и допустимы. То есть охранник либо считает легаси-диапазон нарушением на PR в `main`, либо `main`
отстал так, что легаси-файлы выглядят как свежие.

**Что сделать до слияния:** выяснить, какое из двух верно (политика: разрешён ли новый файл в
диапазоне `001`–`029`, если его нет в базе). Если да — охранник должен принимать такие файлы;
если нет — `028`/`029` надо переименовать по правилам до слияния. Проверить на самом PR, а не
локально против устаревшего `main`.
