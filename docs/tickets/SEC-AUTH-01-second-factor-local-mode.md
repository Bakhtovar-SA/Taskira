# SEC-AUTH-01 — второго фактора для локального режима нет

**Статус: открыт.** **Severity: medium.** Найдено в SEC-ASVS-01 (самопроверка ASVS 5.0 L2, 2026-10-06; [docs/security/ASVS-L2.md](../security/ASVS-L2.md)).

- **Требования:** ASVS 5.0: V6.3.3.
- **Факт:**
  - Локальный режим и break-glass администратор — один пароль (`docs/SECURITY_OVERVIEW.md`: «2FA в Taskira отсутствует»). Для LDAP фактор определяют политики AD.
  - V6.3.3 (L2) требует MFA или комбинацию однофакторных механизмов.
- **Почему важно:** глобальный администратор — самая ценная учётка (экспорт данных, токены, вебхуки); у клиентов без LDAP она защищена одним паролем.
- **Решение:** принять риск: Taskira ставится внутри корпоративной сети, клиенты с требованиями ИБ используют LDAP/AD, где второй фактор обеспечивают политики каталога и корпоративного доступа (VPN, шлюз); TOTP — новая аутентификационная функция (ADR, восстановление, поддержка), несоразмерная до аудита. Условие: до аудита записать принятие риска и компенсирующие меры в SECURITY_OVERVIEW (п. 1, вариант «явное принятие»).
- **Что сделать:**
  1. Решить через ADR: TOTP (RFC 6238) для локальных учёток, обязательный для глобальных администраторов, либо явное принятие риска с компенсирующими мерами (доступ только из корпоративной сети, break-glass только локально) и запись в SECURITY_OVERVIEW.
  2. Если TOTP: секреты шифруются (`secretBox`), одноразовость кода (V6.5.1), коды восстановления, лимиты на проверку, аудит; сброс — по процедуре с подтверждением личности (V6.4.4).
- **Критерий готовности:** принято решение в ADR; при реализации — тесты на одноразовость и перебор, строки V6.3.3/V6.4.4/V6.5.x пересмотрены.
- **Не сделано:** ничего из перечисленного.
