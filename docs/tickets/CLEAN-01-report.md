# CLEAN-01 — чистка репозитория от корпоративных данных: отчёт

**Итог:** в отслеживаемом дереве и в истории git реальных корпоративных данных не найдено. Локальные дампы
удалены; `.gitignore` дополнен; три строки документации с «похожими на настоящие» именами заменены на
зарезервированные. История не переписывалась (по ТЗ).

## Не сделано и почему

- **Профиль `dev` с тестовым LDAP в корневом `docker-compose.yml` не добавлен.** Этот файл генерируется
  `scripts/render-compose.sh` и разворачивается релизным инсталлятором; правка генератора без возможности
  поднять Docker (его нет на этой машине) — непроверенное изменение поставляемой конфигурации. Кроме того,
  сам сервис в compose не получает `LDAP_*`-переменных, так что «демо с тестовым LDAP одной командой» —
  это отдельная задача (генератор + переменные + проверка на машине с Docker), а не профиль в готовом файле.
  Текущее решение (отдельный файл вне дистрибутива) требование «в прод не попадает» выполняет.
- **Реальных пользователей в истории git не искал по содержимому**: искать нечем без списка того, что считать
  реальным; проверены пути (изображения, дампы, `.env`) и типовые паттерны.
- `git status` не чистый из-за `PERFORMANCE.md` в корне: это чужой файл, я его не трогал.
