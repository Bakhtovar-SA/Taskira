# SEC-DOC-01 — документация ASVS L2: правила валидации/лимитов, полевая авторизация, классификация данных

**Статус: открыт.** **Severity: low.** Найдено в SEC-ASVS-01 (самопроверка ASVS 5.0 L2, 2026-10-06; [docs/security/ASVS-L2.md](../security/ASVS-L2.md)).

- **Требования:** ASVS 5.0: V2.1.2, V2.1.3, V8.1.2, V8.2.3, V14.1.1, V14.1.2, V14.2.4.
- **Факт:**
  - Нет единых документов: контекстных правил проверки (V2.1.2), сводной таблицы лимитов на пользователя и глобальных (V2.1.3), правил доступа на уровне полей (V8.1.2), классификации данных и требований к защите по уровням (V14.1.1/14.1.2).
  - Набор полей пользователя, видимых любому участнику проекта (`username`, `phone`), не аудировался (V8.2.3).
- **Почему важно:** это документальные требования L2: без них при внешнем аудите строки остаются «нет» независимо от качества кода.
- **Что сделать:**
  1. `docs/security/DATA-CLASSIFICATION.md`: категории данных (учётные данные, токены, персональные данные из AD, содержимое задач, вложения, аудит) → уровень → хранение, шифрование, логирование, retention, доступ.
  2. Раздел SECURITY_OVERVIEW «Лимиты и бизнес-правила» (единая таблица с таблицей SEC-RATE-01) и «Доступ к полям».
  3. Аудит DTO пользователей в ответах для не-администраторов (bootstrap проекта, пикеры) — сверить с минимально необходимым и записать.
- **Критерий готовности:** документы в репозитории; строки V2.1.2, V2.1.3, V8.1.2, V8.2.3, V14.1.x пересмотрены.
- **Не сделано:** ничего из перечисленного.
