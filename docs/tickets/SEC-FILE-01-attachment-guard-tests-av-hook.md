# SEC-FILE-01 — загрузка файлов: guard без автотестов, нет антивирусной проверки, мягкий лимит вложений

**Статус: открыт.** **Severity: medium.** Найдено в SEC-ASVS-01 (самопроверка ASVS 5.0 L2, 2026-10-06; [docs/security/ASVS-L2.md](../security/ASVS-L2.md)).

- **Требования:** ASVS 5.0: V5.2.2, V5.4.3, V2.3.2 (дополнительная глава V5 — вне перечня тикета, но релевантна загрузке).
- **Факт:**
  - `checkUpload` (`services/fileGuard.ts:208-235`) — центральный барьер загрузки — не покрыт автотестами (поиск `checkUpload`/`ATTACHMENT_REJECTED` в `server/test` пуст). Проба 2026-10-06 подтвердила базовые случаи; выявлено: проверяется только последнее расширение (`shell.php.jpg` с настоящим JPEG принимается).
  - Антивирусной проверки (и точки подключения внешнего сканера) нет (V5.4.3).
  - Лимит вложений на задачу — мягкий, гонка `count → insert` допускает превышение (`services/attachments.ts:147-150`).
- **Почему важно:** загрузка файлов — главная поверхность атаки, а регрессию в guard сейчас никто не заметит.
- **Что сделать:**
  1. Тесты `fileGuard.test.ts` по пробе: исполняемые сигнатуры, несовпадение расширения, двойные расширения, CRLF/путь/зарезервированные имена, BOM-XML, регистр расширения; тест маршрута на 400/413/409 и заголовки скачивания.
  2. Проверять все сегменты расширения по блок-списку (`a.php.jpg`) либо документировать, что тип обеспечивает `attachment`+`octet-stream`.
  3. Хук `ATTACH_SCAN_COMMAND`/ICAP/clamd: файл не становится доступным, пока сканер не вернул чисто; режим «выключено» остаётся по умолчанию; документ в `STORAGE_SETUP.md`.
  4. Атомарный лимит вложений (advisory lock по задаче) либо принять и записать как мягкий.
- **Критерий готовности:** тесты в CI; описание сканера и выбора поведения при его отказе; строки V5.2.2, V5.4.3, V2.3.2 пересмотрены.
- **Не сделано:** ничего из перечисленного.
