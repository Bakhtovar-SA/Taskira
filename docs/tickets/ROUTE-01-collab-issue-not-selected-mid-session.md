# ROUTE-01 — прямая ссылка на приглашённую (collab) задачу mid-session не выбирает карточку

**Статус: открыт, не блокирует ТЗ 3.2.** Найдено при реализации ТЗ 3.1 (роутинг, план v2 Трек 3), 2026-09-22.

- **Файл:** `src/useRouterSync.ts` (эффект «URL → состояние»), ветка `data.collaborations.some(...)`.
- **Симптом:** переход по `/p/:projectKey/issue/:issueKey` на задачу, к которой пользователь приглашён (issue
  collaborator), а не член проекта, **при свежем входе/логине** (`bootstrap()`, `src/store/session.ts`) корректно
  открывает раздел «Мои подключения» с выбранной карточкой (`ui.collabOpenIssueId`). Тот же переход **посреди уже
  открытой сессии** (вставили ссылку в адресную строку / кликнули по ней, пока приложение уже в проекте) переключает
  вид на «Мои подключения», но карточку не выбирает — список остаётся, нужный элемент нужно найти вручную.
- **Причина:** `bootstrap()` имеет прямой доступ к внутреннему `setUi` и пишет `collabOpenIssueId` сама; `useRouterSync`
  работает только через публичный `Api` стора (`src/store.tsx`), где такого сеттера для mid-session-ветки нет —
  выставлен `setView("collaborating")`, и на этом решили не расширять публичный API под узкий случай.
- **Тот же класс, что PERF-06:** «работает на входе, не работает на уже открытой сессии» — кэш/состояние, не знающее
  всех путей, которыми до него добираются.
- **Проверка после починки:** зайти в проект A под пользователем, приглашённым к задаче в проекте B (не членом B);
  вставить в адресную строку `/p/B/issue/<ключ>` — раздел «Мои подключения» открывается с этой карточкой выбранной,
  как при свежем логине. Юнит-тест по образцу `App.routerSync.test.tsx`.
