# SCOPE — Taskira

Внутренний корпоративный трекер задач для компании с несколькими отделами/департаментами.
Аутентификация через LDAP/AD. Работает на собственном сервере (on-prem).

Цель: гибкий и удобный инструмент уровня Jira, но **без узкоспециализированного сленга
разработчиков** — им должны одинаково комфортно пользоваться ИБ, HR, бухгалтерия,
разработка и любой другой отдел.

## Терминология (без жаргона)

| Не используем (Jira-сленг) | Используем вместо |
|---|---|
| Epic / эпик | Направление |
| Sprint / спринт | — (не используется) |
| Story points | Сложность (низкая / средняя / высокая) |
| Backlog | Список задач |
| Board | Доска |
| Issue | Задача |
| JQL | — (не используется, обычные фильтры в UI) |

## Иерархия доступа

Организация → Департамент (отдел) → Проект(ы) отдела → Задачи

- Департамент соответствует группе в LDAP/AD.
- У департамента может быть один или несколько проектов.
- Проект по умолчанию виден только участникам своего департамента.
- Отдельно поддерживаются "общие" (кросс-департаментные) проекты — для задач,
  где участвует несколько отделов (например, ИБ + IT + юридический).

## Роли и права (по проекту, не глобально)

Роль пользователя назначается **в рамках конкретного проекта**, а не на всё приложение —
один и тот же человек может быть менеджером в своём проекте и наблюдателем в чужом,
если ему открыли доступ.

| Роль | Что может |
|---|---|
| Администратор | Всё: настройка проектов, отделов, статусов, прав |
| Менеджер проекта | Создание/редактирование/удаление задач своего проекта, управление составом |
| Исполнитель | Создание задач, смена статусов, комментарии; редактирует только свои задачи |
| Наблюдатель | Только просмотр |

## В рамках MVP (входит)

- Департаменты и проекты (иерархия доступа выше)
- Задачи: название, описание, статус, исполнитель, автор, приоритет, сложность, метки, комментарии, история изменений
- Доска (канбан) по статусам, drag&drop
- Список задач (без временных итераций/спринтов) — плоский список с фильтрами
- Направления — опциональная группировка связанных задач (замена эпиков, без жёсткой иерархии)
- Настраиваемые статусы и переходы между ними (админ)
- Ролевая система доступа, привязанная к проекту
- Аутентификация через LDAP/AD, синхронизация членства в департаменте по группе AD
- Уведомления (в приложении + email) о назначении задачи, смене статуса, упоминании
- Вложения к задачам (файлы)
- Глобальный поиск и фильтры (без JQL — обычные выпадающие фильтры)

## Осознанно откладываем / не делаем

- Спринты, scrum-церемонии, оценка в story points
- JQL и любой язык запросов
- Конструктор автоматизации с условиями ("если поле = X, то сделать Y") — вместо этого
  простая валидация переходов статусов (уже реализована в текущем коде)
- Тайм-трекинг, биллинг, отчётность по трудозатратам
- Множественные workflow-схемы на проект (пока одна схема статусов на проект достаточно)

## Открытые вопросы (требуют решения перед разработкой)

- Как именно мапить группы LDAP/AD на департаменты (по OU, по группе безопасности?)
- Нужны ли кросс-департаментные проекты в MVP или это следующая итерация
- Формат уведомлений: только в приложении, или обязательно email через корпоративный SMTP
