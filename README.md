# Taskira — трекер задач в духе Jira

Полнофункциональный клон Jira, работающий целиком в браузере: канбан-доска с drag&drop,
бэклог со спринтами, таймлайн эпиков, настраиваемый workflow и **ролевая система прав доступа**.
Данные сохраняются в `localStorage`, сервер не требуется.

## Возможности

| Раздел | Что умеет |
| --- | --- |
| **Доска** | Колонки = статусы workflow; drag&drop с валидацией переходов и прав; быстрое создание в колонке; фильтры по исполнителю и тексту; счётчики задач и story points |
| **Бэклог** | Активный / будущий спринт / бэклог; перенос задач между секциями; старт и завершение спринта с авто-возвратом недозакрытых задач |
| **Таймлайн** | Эпики на 8-недельной шкале, прогресс закрытия, линия «сегодня», раскрытие дочерних задач |
| **Рабочий процесс** | SVG-граф статусов и переходов; добавление/удаление переходов (только администратор); изменения сразу действуют на доске |
| **Права доступа** | Матрица разрешений «роль × право», состав команды, демо-переключение пользователей |
| **Документация** | Встроенный справочник (роли, workflow, модель данных, горячие клавиши) |
| **Карточка задачи** | Inline-редактирование названия и описания, статус/исполнитель/приоритет/эпик/спринт/оценка/метки, комментарии, история изменений, удаление |
| **Сквозное** | Глобальный поиск (`/`), горячие клавиши, уведомления, тосты, сохранение состояния |

## Система прав доступа

Двухуровневая модель (как в Jira Permission Schemes):

1. **Ролевой уровень** — матрица `MATRIX` в `src/permissions.ts` определяет, каким ролям доступно каждое разрешение.
2. **Уровень задачи** — разрешение *edit* для разработчика сужается: редактировать можно только задачи, где он **исполнитель** или **автор**.

### Роли

| Роль | Описание |
| --- | --- |
| 🔴 **Администратор** | Всё, включая изменение workflow и просмотр матрицы прав. В сиде — Анна Соколова |

| ⚪ **Наблюдатель** | Только чтение: видит всё, не меняет ничего. В сиде — Елена Волкова |

### Матрица разрешений

| Разрешение | admin | manager | developer | viewer |
| --- | :-: | :-: | :-: | :-: |
| Просмотр проекта | ✓ | ✓ | ✓ | ✓ |
| Создание задач | ✓ | ✓ | ✓ | — |
| Редактирование задач | ✓ | ✓ | ✓* | — |
| Смена статуса (переходы workflow) | ✓ | ✓ | ✓ | — |
| Удаление задач | ✓ | ✓ | — | — |
| Комментарии | ✓ | ✓ | ✓ | — |
| Управление спринтами | ✓ | ✓ | — | — |
| Изменение workflow | ✓ | — | — | — |
| Управление доступом | ✓ | — | — | — |

\* — только задачи, где разработчик является исполнителем или автором.

### Enforcement (где проверяются права)

- **`src/store.tsx` → `requirePerm()`** — каждая мутация (create/update/move/sprint/comment/delete/workflow)
  проверяется до изменения данных; отказ сопровождается тостом с человекочитаемой причиной (`denialReason()`).
- **UI-слой** — недоступные элементы скрываются или блокируются: кнопка «Создать» с замком, плашка
  «только чтение» на доске, `LockedField` с тултипом в карточке, неактивные кнопки спринтов.
- **Проверка в двух местах** сознательна: UI даёт мгновенную обратную связь, store гарантирует целостность.

Демо-переключение ролей: меню пользователя (справа сверху) → «Войти как…» или раздел «Права доступа».

## Workflow

Ориентированный граф статусов (`src/seed.ts → DEFAULT_WORKFLOW`):

```
К выполнению ──► В работе ──► На ревью ──► Готово
     │              │  ▲         │  ▲         │
     │              ▼  └─────────┘  └─────────┘
     └────────────────────────────► Готово
Готово ──► В работе (переоткрытие)
```

- Смена статуса любым способом (drag, меню карточки) валидируется схемой: запрещённые переходы отклоняются.
- Администратор добавляет/удаляет переходы в разделе «Рабочий процесс» — изменения применяются мгновенно.
- Workflow и права проверяются независимо: даже администратор не перетащит задачу против схемы.

### Слой доступа в коде

```ts
// permissions.ts — единая точка проверки
can(user, "edit", issue)          // false для чужой задачи у разработчика
can(user, "manageSprints")        // false для developer/viewer
denialReason(user, "edit", issue) // «Роль „Разработчик" может редактировать только свои задачи…»

// store.tsx — защита мутаций
const updateIssue = (id, patch) => {
  const iss = …;
  if (!requirePerm("edit", iss)) return;   // тост-отказ, данные не меняются
  …
};
```

## Модель данных

- **Project** `{key, name, description}` — корневая сущность (`ATL «Атлас»`).
- **User** `{id, name, role (должность), accessRole (права), color, initials}`.
- **Issue** `{key: "ATL-N", typeId, statusId, priorityId, assigneeId, reporterId, epicId, labels[], points, sprintId, comments[], activity[]}`.
- **Sprint** `{name, goal, status: future|active|completed, startDate, endDate}`.
- **Workflow** `{statuses: [{id, name, category}], transitions: [{from, to}]}`.

## Хранение

- Ключ `localStorage`: `taskira.v1`. Сохраняются задачи, спринты, workflow, счётчик номеров.
- Пользователи и роли — константа сида; при загрузке выполняется **миграция** (старым данным без `accessRole` присваиваются роли из сида).
- «Сбросить демо-данные» (сайдбар) возвращает исходный проект.

## Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `/` | Фокус на глобальный поиск |
| `C` | Создать задачу (если роль позволяет) |
| `1–6` | Доска, Бэклог, Таймлайн, Workflow, Права, Документация |
| `Esc` | Закрыть модальное окно |
| `Ctrl+Enter` | Отправить комментарий |
